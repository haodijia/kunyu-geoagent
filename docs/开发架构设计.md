# 坤舆智枢开发架构设计

> 文档状态：新开发基线
> 适用范围：Electron 桌面端、React 前端、FastAPI 后端、自研 DSH Agent 与 OGE 集成
> 当前阶段：已形成 v3 对话、地图与模型设置原型；工作区外壳、对话/轨迹关系、地图交互和多模型连接按本文执行。概览与 GeoSkill 的 v3 稿仍可继续细化，但不得改变本文冻结的状态模型。

## 1. 架构决策摘要

本次调整形成以下基线。

1. **Agent 是核心任务工作区。** 产品采用类似 Codex 的桌面布局：左侧管理全局入口、置顶任务与最近项目，主区承载同一线程的概览、分析与地图投影；设置使用独立全页空间。
2. **以线程组织工作。** 用户进入应用后创建或恢复一个任务线程；一次自然语言请求、计划确认、工具执行、OGE 长任务、结果解释和导出都留在同一线程中。
3. **自研最小 DSH。** DSH 是本项目内部的 Python Agent 框架，参考 DeepSeek Harness 的插件化、能力接缝、类型事件和可恢复会话日志思想，不复制其 TypeScript/Cordis 实现。
4. **仓库顶层固定为 `electron/`、`frontend/`、`backend/`。** Electron 是桌面壳和本地进程管理器，React 只负责界面，FastAPI 承载业务、DSH、OGE 适配和持久任务。
5. **Electron 负责拉起 FastAPI。** 后端仅监听本机回环地址，准备完成后 Electron 才加载 React；退出应用时由 Electron 请求后端优雅停止并回收进程。
6. **首版不引入 Redis、Celery 和 PostgreSQL。** 本地示例采用 FastAPI 单进程、SQLite 和本地成果目录，OGE 承担真正的遥感计算。只有出现并发部署或团队服务化需要时，再拆独立 Worker 和 PostgreSQL/PostGIS。
7. **对话与轨迹属于同一个分析工作区。** 顶部控制器不是四个平级 Tab，而是 `概览 | [对话 ↔ 轨迹] | 地图` 三个一级区域；轨迹只展示可审计事件，不展示隐藏推理。
8. **模型连接与单次运行选择分离。** 设置页管理多个模型连接；线程输入框选择连接、模型和推理强度；Run 创建时冻结选择快照，运行中不热切换。
9. **示例只打通一条纵向链路。** 以“榕江县洪涝影响研判”为唯一完整示例，证明自然语言输入、GeoSkill 约束计划、人工确认、OGE 作业、地图成果和带引用解释能够闭环。
10. **首期不做 Agent 装配页。** DSH 插件和能力由后端启动代码显式装配；业务用户通过 GeoSkill 选择场景方法，通过设置页管理运行连接，不在界面中自由拼装 Agent、Tool 或提示词。

整体设计遵循赛事方案确定的业务目标、OGE 路线、GeoSkill、Memory、证据链和人工确认原则。

## 2. 目标与边界

### 2.1 产品目标

坤舆智枢是面向灾害遥感监测与研判的桌面任务工作区。用户用自然语言描述研判目标，DSH 根据当前项目、地图选择和 GeoSkill 形成可确认的范围、时段与输出快照；用户确认后，确定性业务服务调用 OGE 完成计算，并把结果作为地图、统计、核查清单和报告 Artifact 返回当前线程。

首期完整链路为：

**新建任务线程 → 描述榕江洪涝研判目标 → 检查并确认分析快照 → 调用 OGE → 查看地图与统计 Artifact → 复核重点对象 → 导出带来源的研判报告。**

平台仍需响应赛事的五类要求：

- 形成“数据接入—信息提取—影响研判—核查反馈—成果更新”的业务闭环；
- 深度使用 OGE 的数据、算子、在线计算和前序成果引用；
- 提供可复用的 FastAPI WebService；
- 保持 Electron、React、FastAPI、DSH 和 OGE 的模块边界；
- 用任务线程、动态 Artifact 和地图联动体现交互创新。

### 2.2 首期范围

- Electron 桌面启动、单实例、后端进程管理和错误诊断；
- 项目与任务线程创建、恢复、重命名和归档；
- DSH 会话、运行、计划、确认、工具调用、等待和恢复；
- 洪涝 GeoSkill、项目上下文和最小 Memory；
- GeoSkill 目录、版本详情和从场景创建任务；
- 模型、OGE、本地存储、安全与系统状态设置；
- OGE 产品/影像查询、已发布服务执行、状态查询和成果读取；
- 对话、审计轨迹、地图、图层、统计、任务详情、引用定位和 Markdown 报告 Artifact；
- 多模型连接、默认模型以及线程级模型选择；
- 榕江县洪涝影响研判的真实纵向示例；
- FastAPI OpenAPI 文档与同能力的外部调用接口。

### 2.3 首期明确不做

- 通用多 Agent 协作、自治 Agent 群或模型自行创建子 Agent；
- DSH 插件市场、动态下载、热更新或复杂依赖求解；
- Agent 自由装配、角色市场、人格提示词编辑和可视化 Tool 拓扑；
- 在运行中途切换模型连接、模型或推理强度；
- 在 GUI 中新建、编辑或发布 GeoSkill；首期场景包随源码交付，页面只读；
- 通用可视化工作流编辑器；
- Redis、Celery、Kafka、微服务和多数据库兼容层；
- 多租户计费、复杂组织权限和云端账号体系；
- Agent 直接执行 SQL、任意 Python、Shell 或原始 OGE 请求；
- 移动端、实时多人协作和完整三维场景；
- 同时实现多个灾种的完整业务链。

## 3. 交互架构：Agent 是工作区，不是侧栏

### 3.1 核心界面模型

页面以 `Project → Thread → Run → Artifact` 组织。

- `Project`：一个持续研判空间，保存研究区、事件、资产和历史成果。
- `Thread`：用户可见的工作单元，承载对话、确认、可审计轨迹和成果入口。
- `Run`：线程中一次用户请求触发的 Agent 运行。
- `Artifact`：运行产生或打开的业务对象，例如地图、图层、统计、任务详情和报告。

Agent 能力始终属于当前线程，不作为地图右侧临时挂载的附属聊天框。Artifact 是线程的版本化业务产物；地图作为一级工作区投影打开，其他 Artifact 可从对话、轨迹或地图结果入口进入详情。

### 3.2 桌面布局

默认窗口以 `1600 × 1000` 为设计基准，最小窗口为 `1200 × 760`。左侧栏展开宽度为 `320px`，收起后为 `56px`；所有“居中”元素都相对于扣除侧栏后的主内容区计算，不相对于整个窗口计算。

```text
┌──── 侧栏 320 / 56 px ────┬──────────────────────── 主内容区 ───────────────────────────────┐
│ 收起 / 后退 / 前进        │ 项目面包屑       概览 | [对话↔轨迹] | 地图       状态 / 分享   │
│ Kunyu / 搜索 / 通知       ├───────────────────────────────────────────────────────────────┤
│ 新建任务                  │                                                               │
│ GeoSkill                  │              同一 ThreadWorkspace 的当前投影                  │
│ 探索                      │                                                               │
│                           │  对话：连续 Agent 消息与内联活动                              │
│ 置顶                      │  轨迹：可审计事件                                              │
│  项目 / 任务              │  地图：全幅 GIS + 轻量 Agent 输入框                            │
│ 最近                      │                                                               │
│                           │                                                               │
│ 设置                      │                                                               │
└───────────────────────────┴───────────────────────────────────────────────────────────────┘
```

布局规则：

- 侧栏第一行固定为收起、后退和前进；第二行是产品身份、搜索和通知；中部按“置顶/最近”组织任务；底部只保留设置。
- `GeoSkill` 与“探索”属于全局入口，不放在侧栏底部；设置进入后使用独立的设置导航，不复用任务树。
- 顶部模式控制器精确居中于主内容区，右侧运行状态、分享和更多操作不参与其居中计算。
- 模式控制器视觉上包含四个图标，但语义上是三个一级区域：左侧概览、中间分析、右侧地图；分析区域内部再以滑块切换对话和轨迹。
- 对话正文使用约 `880–960px` 的舒适阅读宽度；底部输入框约 `850–900px`，上下文与模型选择采用轻量文本控件，不使用大面积表单框。
- 地图模式使用完整主内容区，不再默认把对话压成固定右侧栏；地图上只保留轻量输入框、结果提示和必要 GIS 控件。
- 侧栏折叠、主模式切换和地图视图切换不得重建 Thread、Run、地图实例或 SSE 订阅。

### 3.3 线程中的内容块

对话采用 Codex 式连续 Agent 记录，不渲染成预先编排的工作流。用户消息右对齐，Agent 文本左对齐；工具和数据动作以短活动行穿插在回复中。每条运行可渲染下列内容：

| 内容块 | 用途 | 主要操作 |
| --- | --- | --- |
| 用户请求 | 保存原始目标与附带地图上下文 | 编辑并重新运行 |
| 补充问题 | 只询问阻塞执行的必要信息 | 选择、输入、取消 |
| 活动行 | 显示“已读取、已检索、已核对、正在调用”等用户可理解动作 | 展开对应轨迹项 |
| 确认快照 | 只显示范围、时段、输出和副作用摘要 | 调整、确认、拒绝 |
| Artifact 卡片 | 表示地图、统计、报告或核查清单 | 在工作区打开 |
| 引用化结论 | 给出结论、观测限制和证据引用 | 点击定位成果或图斑 |
| 后续动作 | 提供复核、导出、基于结果继续分析 | 明确按钮触发 |

对话中禁止出现 `3/6`、固定六步流程或持续进度条来暗示 Agent 是静态 Workflow。确定性 Task 可以有步骤，但步骤只在轨迹或任务详情中展示。模型内部推理不展示也不持久化；轨迹只记录用户可理解的操作、工具摘要、状态、错误、引用和产物。

### 3.4 Artifact 工作区

首期只实现五类 Artifact：

1. `map`：OpenLayers 地图、图层树、图例、卷帘和图斑详情；
2. `metrics`：乡镇统计、覆盖率和简单图表；
3. `task`：确定性任务步骤、OGE `processId`、耗时和错误摘要；
4. `inspection-list`：待核查对象、优先级、状态和地图定位；
5. `report`：基于指定成果版本生成的 Markdown 预览与导出。

Artifact 通过稳定标识关联业务对象，而不是把大段数据塞进消息正文。地图 Artifact 在地图模式中成为完整主工作区；统计、任务和报告可从对话卡片或地图结果入口打开，不强制采用三栏分屏：

```ts
interface ArtifactRef {
  artifactId: string
  kind: 'map' | 'metrics' | 'task' | 'inspection-list' | 'report'
  title: string
  resourceType: string
  resourceId: string
  resultSetId?: string
}
```

### 3.5 页面与导航

桌面端采用单窗口、任务优先导航。任务侧栏和设置侧栏是两套互斥 Shell：

| 位置 | 页面/视图 | 说明 |
| --- | --- | --- |
| 启动页 | 最近项目与新建任务 | 启动后第一入口 |
| 线程概览 | 摘要、成果、项目记忆、数据和最近活动 | 快速恢复任务上下文 |
| 分析/对话 | 消息、确认快照、内联活动和结果 | 发起并推进 Agent Run |
| 分析/轨迹 | Agent、Tool、Task 与 Artifact 的可审计事件 | 诊断、追踪和打开证据，不展示思维链 |
| 线程地图 | 全幅地图 Artifact + 轻量输入框 | 浏览成果并把空间选择加入上下文 |
| GeoSkill | 场景目录与版本详情 | 查看输入输出、工作流、质量规则和验证案例 |
| 探索 | 后续跨项目发现入口 | 首期仅保留导航位，不提前建设内容聚合 |
| 设置 | 独立全页设置空间 | 管理连接、能力、数据、安全、健康和关于 |

前端内部可使用 Hash Router，以适配 Electron 打包后的本地资源加载；用户主要通过左侧线程导航，而不是感知复杂 URL。

### 3.6 页面状态与路由

概览、分析和地图不是三种业务对象，而是同一 `ThreadWorkspace` 的三个一级投影；分析内部包含对话与轨迹两个二级投影。四个图标对应四个路由叶子，但不是四个平级业务 Tab。

```ts
type WorkspaceMode = 'overview' | 'analysis' | 'map'
type AnalysisMode = 'conversation' | 'trace'

interface ThreadWorkspaceUiState {
  workspaceMode: WorkspaceMode
  analysisMode: AnalysisMode
  sidebarCollapsed: boolean
  composerDraft: string
  mapViewport: MapViewport
}
```

切换一级或二级投影时，共享当前线程、活动 Run、Artifact、地图选择、输入草稿和流式订阅；不得重复请求、复制消息或创建新会话。返回分析区域时恢复上一次 `analysisMode`。

| 路由 | 页面状态 | 数据来源 |
| --- | --- | --- |
| `#/projects/:projectId/threads/:threadId/overview` | 线程概览 | Thread 聚合查询 |
| `#/projects/:projectId/threads/:threadId/analysis/conversation` | 原始对话 | Message、Run、Confirmation、ArtifactRef |
| `#/projects/:projectId/threads/:threadId/analysis/trace` | 审计轨迹 | TraceEntry 投影 |
| `#/projects/:projectId/threads/:threadId/map` | 地图 Artifact | Artifact、ResultSet、MapContext |
| `#/geoskills` | GeoSkill 目录 | SceneVersion 摘要 |
| `#/geoskills/:sceneId/:version` | GeoSkill 版本详情 | 已发布场景包投影 |
| `#/settings/:section` | 独立设置分区 | Settings、ModelConnection 与 SystemStatus |
| `#/settings/models/:connectionId` | 模型连接详情 | 脱敏连接、模型目录和测试结果 |

地图页默认保留紧凑输入框和可关闭的结果提示。需要查看完整上下文时切换回分析区域；切换过程中地图视口、选中图斑、可见图层和输入草稿保持不变。Run 等待确认或失败时只显示通知与状态，不自动用大面板遮挡地图。

### 3.7 GeoSkill 页面

GeoSkill 页面负责回答“系统会做什么、需要什么、会产出什么”，不是提示词仓库或 Agent 插件市场。它使用与任务页相同的产品 Shell，但目录内容保持平面、稀疏，不增加统计看板或多层分栏。

首期目录页实现：

- 按名称、灾种和状态筛选已随应用交付的 GeoSkill；
- 查看版本、能力标签、输入输出、工作流、质量规则、展示配置和验证案例；
- 从指定 `SceneVersion` 创建任务，创建后的 Task 永久锁定该版本；
- 展示场景包校验结果和 OGE 能力依赖是否满足；
- 不允许在 GUI 中直接编辑 YAML、Markdown 或发布新版本。

旧版 `geoskill-editor-v2.png` 只作为历史探索稿。只有首条洪涝链路稳定后才决定是否实现草稿、Schema 校验、验证案例和发布；若实现，仍采用结构化表单和有序步骤，不做自由连线画布。场景发布属于人工管理操作，不开放给 Agent Tool。

### 3.8 设置页面

设置页参考 Maka 的独立全页结构：进入设置后隐藏任务树和线程模式控制器，左侧显示“返回应用”和分组导航，右侧只呈现当前设置分区。导航分组为：

- 偏好：通用、外观；
- 能力：模型、GeoSkill、记忆、远程接入；
- 数据与系统：数据、权限与安全、运行健康、关于。

首期设置分区如下：

| 分区 | 可配置内容 | 写入位置 |
| --- | --- | --- |
| 通用 / 外观 | 启动行为、语言、主题和界面密度 | SQLite 中的用户偏好 |
| 模型 | 多个连接、Provider、Base URL、可用模型、默认连接、写入型 API Key、连接测试 | 非秘密配置写 SQLite，密钥写系统凭据库 |
| GeoSkill | 已安装场景包、依赖状态和启停状态 | SQLite + 内置场景目录；首期只读 |
| 记忆 | Thread/Project/Case Memory 开关和清理入口 | SQLite |
| 远程接入 | OGE Base URL、鉴权 Profile、AppKey/JWT 配置状态、连接测试 | 非秘密配置写 SQLite，凭据写系统凭据库 |
| 数据 | 数据目录、占用空间、导出目录和清理入口 | SQLite + 应用数据目录 |
| 权限与安全 | 日志级别、脱敏说明、凭据状态和数据清理 | SQLite；不显示密钥原文 |
| 运行健康 | 后端、数据库、OGE 和模型连接诊断 | 运行时投影，不持久化为业务事实 |
| 关于 | 应用、API、DSH 和场景包版本 | 构建信息与后端状态 |

模型设置首页是平面连接列表，不是单一 Provider 表单。每个 `ModelConnection` 拥有显示名、Provider 类型、Base URL、可用模型目录、连接状态和默认标记；点击后进入连接详情。允许存在多个连接，但只能有一个全局默认连接。

密钥输入框是写入控件，不是可读取字段。前端只能获得 `configured`、更新时间和可选尾号，不能通过 API 取回明文。连接测试和模型目录发现均由 FastAPI 发起，React 不直连模型或 OGE。

输入框中的模型选择器读取可用连接和模型，线程保存最近一次选择用于下次预填；每次发送消息时必须把 `connection_id`、`model_id` 和 `reasoning_effort` 传给后端并冻结为 Run 快照。删除连接前必须检查其是否为默认连接或被未完成 Run 引用。

### 3.9 为什么没有 Agent 装配页

首期只有一个受控 `GeoAgent` 运行角色。其模型、上下文、Tool、GeoSkill、Memory、Policy 和 EventStore 在 `kunyu.agent.bootstrap` 中显式装配，属于可测试、可审计的系统启动配置。

```text
GeoAgent（固定运行角色）
├── Model Router         ← 从多个 ModelConnection 解析 Run 快照
├── Context Provider     ← 项目、线程、地图与成果
├── Tool Registry        ← 后端代码注册白名单 Tool
├── GeoSkill Resolver    ← 任务锁定已发布 SceneVersion
├── Memory Provider      ← Thread / Project / Case Memory
├── Policy Gate          ← 副作用、确认、预算与权限
└── Event Store          ← SQLite 追加事件
```

独立装配页会要求动态插件发现、依赖求解、权限编辑、配置 Schema、运行隔离和兼容性验证，这与“自研最小 DSH”和单一洪涝纵向示例相冲突。以后若确有多角色需求，只新增由代码定义的 `AgentProfile` 下拉选择，并把 `profile_id` 快照到 Run；仍不允许用户任意拼装插件。

## 4. 首个示例：榕江洪涝研判线程

现有 `docs/ui-mockups/` 的 v3 基线已覆盖对话、地图和模型设置；概览与 GeoSkill 后续稿必须复用同一 Shell 和状态模型。首版仍以一条可验收的纵向示例确定组件，不因页面齐全而提前铺开多灾种业务。

### 4.1 示例入口

启动页提供一个主按钮“新建研判任务”和一个示例提示：

### 4.3 示例页面状态

示例只需覆盖下列状态：

1. **空线程**：显示可使用的场景和一条示例目标；
2. **准备中**：对话内流式展示“已读取、已检索、已核对”等简短活动，不展示模型思维链；
3. **待确认**：线程内出现只含范围、时段、输出和副作用摘要的确认快照；
4. **执行中**：对话只显示当前活动，完整 Tool/Task 状态进入轨迹视图；

- 用户不接触 OGE URL、AppKey、原始请求或内部文件路径；

- OGE `processId` 可在任务 Artifact 中追踪；

- Agent 回答中的日期、面积、排名和图斑判断可点击定位到证据；
- 应用重启后线程、任务和 Artifact 可恢复。

## 5. 进程与系统架构

### 5.1 桌面运行架构

```mermaid
flowchart LR
    subgraph Desktop[Electron 桌面应用]
        MAIN[Electron Main\n窗口与进程生命周期]
        PRELOAD[Preload\n最小 IPC Bridge]
        FE[React Renderer\n线程与 Artifact]
        MAIN --> PRELOAD --> FE
    end

    MAIN -->|spawn / stop| API[FastAPI 本地后端\n127.0.0.1:随机端口]
    FE -->|REST + SSE\n每次启动令牌| API

    subgraph Backend[FastAPI 进程]
        APP[应用服务]
        DSH[自研 DSH]
        MODELS[Model Router\n连接解析与运行快照]
        JOB[持久任务监督器]
        OGEADAPTER[OGE Adapter]
        DB[(SQLite)]
        CREDENTIALS[(系统凭据库)]
        FILES[(本地成果目录)]
        API --> APP
        APP --> DSH
        DSH --> MODELS
        APP --> JOB
        APP --> DB
        APP --> CREDENTIALS
        JOB --> DB
        JOB --> OGEADAPTER
        APP --> FILES
    end

    OGEADAPTER -->|JWT / tk| OGE[OGE OpenAPI]
    MODELS --> MODEL[模型 API]
```

进程职责：

| 进程 | 负责 | 不负责 |
| --- | --- | --- |
| Electron Main | 单实例、窗口、FastAPI 子进程、系统菜单、文件选择、更新和崩溃诊断 | 不包含业务规则，不直接访问 OGE |
| React Renderer | 任务 Shell、对话/轨迹、Artifact、地图、确认、模型选择和设置投影 | 不拥有密钥，不使用 Node API，不决定任务最终状态 |
| FastAPI | 业务对象、DSH、策略、任务、持久化、OGE 与模型接入 | 不承担 Electron 窗口逻辑 |
| OGE | 遥感数据、算子、组合模型与在线计算 | 不管理本地项目线程和人工确认 |

系统凭据库是 FastAPI 的基础设施依赖，只保存模型与 OGE 密钥。SQLite 保存多个 `ModelConnection`、可公开展示的连接参数和 `configured` 状态，React 只通过脱敏设置 API 访问。Model Router 根据 Run 快照解析唯一连接，不在失败时静默切换到其他 Provider。

### 5.2 服务化部署边界

FastAPI 必须保持可独立启动和提供 OpenAPI 文档，因此桌面端不是唯一入口。赛事需要的 WebService 与桌面端复用相同应用服务和请求模型。

首版只交付本地单进程实现。需要多人访问或持续后台计算时，再形成服务器部署版本：独立 API、Worker、PostgreSQL/PostGIS 与任务队列。该扩展不得改变 `Thread`、`Run`、`Task`、`Artifact` 和 OGE Adapter 的公开契约，但首版不提前实现双存储和双队列兼容代码。

## 7. Electron 启动与安全设计

### 7.1 启动流程

```mermaid
sequenceDiagram
    participant E as Electron Main
    participant B as FastAPI Sidecar
    participant R as React Renderer

    E->>E: 获取单实例锁并创建启动窗口
    E->>E: 生成本次启动 session token
    E->>B: 启动后端进程并传入数据目录与 token
    B->>B: 打开 SQLite、恢复未完成任务、绑定随机端口
    B-->>E: stdout 输出单行 ready JSON
    E->>B: GET /api/v1/system/health
    B-->>E: healthy
    E->>R: 加载 React 并通过 preload 提供 baseUrl
    R->>B: REST / SSE + X-Kunyu-Session
```

开发环境启动命令由 Electron 执行：

```text
uv run --project backend python -m kunyu.main --desktop
```

发布包中使用同一后端源码构建 sidecar，可执行文件路径由打包资源确定。Renderer 不自行寻找端口，也不尝试连接系统中其他 FastAPI 实例。

### 7.2 Ready 协议

后端成功启动后只向标准输出写一条机器可读事件：

```json
{"type":"ready","host":"127.0.0.1","port":43127,"pid":8123,"api_version":"1"}
```

Electron 在收到 Ready 且健康检查通过前不加载业务界面。超时、进程退出或协议不匹配时显示诊断页，包含退出码、脱敏后的最近日志和“重新启动后端”按钮。

### 7.3 关闭与恢复

- Electron 退出前调用后端内部 shutdown 接口；
- 后端停止接收新 Run，持久化当前事件和任务检查点；
- Electron 等待有限时间后结束自己创建的子进程；
- 已提交 OGE 的远端任务不视为取消，下一次启动根据 `processId` 恢复查询；
- 不允许两个桌面实例同时写同一 SQLite 文件。

### 7.4 安全边界

- FastAPI 仅绑定 `127.0.0.1` 的随机端口；
- Electron 每次启动生成随机 session token，通过环境变量交给后端，通过 preload 交给 Renderer 内存；
- 所有 API 和 SSE 请求携带 `X-Kunyu-Session`，token 不写入 URL、本地存储和普通日志；
- Electron 开启 `contextIsolation`，关闭 Renderer 的 Node 集成；
- preload 只暴露后端启动信息、文件选择和少量系统能力；
- OGE JWT、AppKey 和模型密钥只由 FastAPI 读写系统凭据库；设置查询只返回是否已配置，不返回明文；
- 外部链接交给系统浏览器，React 不直接导航到不可信页面。

## 8. 前端设计

### 8.1 技术基线

- React + TypeScript + Vite；
- TanStack Query 管理服务端状态；
- Zustand 管理侧栏、工作区模式、选中 Artifact 和地图交互状态；
- OpenLayers 渲染二维地图；
- ECharts 渲染统计图；
- 原生 `EventSource` 无法附加自定义 session header，因此 SSE 客户端使用 `fetch` 流读取；
- 首期不引入 Cesium，三维作为主链完成后的独立 Artifact 类型。

### 8.2 状态边界

| 状态 | 事实来源 | 示例 |
| --- | --- | --- |
| 服务端状态 | FastAPI | 项目、线程、Run、Task、Artifact、成果 |
| 本地界面状态 | Zustand | 侧栏收起、工作区模式、分析子模式、地图视口、图层显隐 |
| 表单草稿 | 组件本地状态 | 确认快照中的可编辑时间和阈值 |
| 线程偏好 | FastAPI | 最近使用的模型连接、模型、推理强度 |
| 流式临时状态 | SSE 客户端 | 当前消息增量、步骤动画 |

SSE 增量只是展示状态。收到完成事件或重连后，前端重新读取对应资源，不用本地事件推导永久业务状态。

### 8.3 地图上下文

用户发消息时只提交明确选择，不把完整地图对象序列化给 Agent：

```ts
interface MapContext {
  projectId: string
  eventId: string | null
  viewport: { longitude: number; latitude: number; zoom: number }
  selectedAoiId: string | null
  selectedFeature: { layerId: string; featureId: string } | null
  activeObservationId: string | null
  comparisonObservationIds: string[]
  activeResultLayerId: string | null
  visibleLayerIds: string[]
}
```

“这里”“这个图斑”“上一期”必须由这些稳定引用解析。无法唯一解析时，DSH 生成补充问题，不猜测对象。

地图原型中的“新增积水 / 耕地影响 / 道路影响”、图层数量、图例、默认时相和选中样式不硬编码在页面组件中，而由 `Artifact.presentation` 与 GeoSkill `presentation.yaml` 投影生成。前端只维护当前专题、2D/3D 显示模式、时间滑杆位置和选中对象；图层 URL、空间参考、统计字段和引用关系来自后端 Artifact DTO。

首期默认实现 2D。若 3D 未进入首期，顶部 `3D` 控件必须以禁用状态明确表达，不能点击后静默回到 2D。

### 8.4 页面查询与本地状态

前端按页面建立查询边界：

| 页面 | 主查询 | 只保存在本地的状态 |
| --- | --- | --- |
| 线程概览 | `thread workspace` 聚合数据 | 卡片折叠状态 |
| 线程对话 | Message、Run、Confirmation、ArtifactRef | 输入草稿、滚动锚点 |
| 线程轨迹 | TraceEntry 分页投影 | 过滤器、展开项、滚动锚点 |
| 线程地图 | Artifact、ResultSet、Layer、Citation | 视口、图层显隐、专题和时间滑杆 |
| GeoSkill | SceneVersion 列表与详情 | 搜索词、选中标签页 |
| 设置/模型 | ModelConnection 列表、模型目录和脱敏凭据状态 | 未提交连接表单草稿 |
| 其他设置 | 脱敏后的 Settings、SystemStatus | 未提交表单草稿 |

线程顶部的一级模式和分析区二级模式都使用路由；侧栏折叠、地图控件和输入草稿使用 Zustand。切换页面时取消页面级临时请求，但不取消服务端 Run 或 Task。设置保存成功后使对应 Query 失效并重新读取脱敏值。

### 8.5 对话活动与轨迹投影

对话内活动行和完整轨迹来自同一服务端投影，不能由前端根据文本猜测。轨迹条目是 `AgentEvent`、Task 事件和 Artifact 事件的用户可见映射：

```ts
interface TraceEntry {
  traceId: string
  threadId: string
  runId: string | null
  occurredAt: string
  category: 'agent' | 'tool' | 'task' | 'artifact' | 'warning'
  status: 'started' | 'waiting' | 'completed' | 'failed'
  title: string
  summary?: string
  durationMs?: number
  resourceRef?: ArtifactRef
  citationIds: string[]
}
```

投影层必须删除模型隐藏推理、未脱敏工具输入、密钥、内部文件路径和完整模型上下文。对话只取每个 Run 的少量关键条目；轨迹页按时间完整分页，并能跳转 Task、Artifact 或 Citation。

### 8.6 GeoSkill 展示模型

前端不解析 `SKILL.md` 或 YAML。后端把已校验场景包投影为稳定 DTO：

```ts
interface SceneVersionDetail {
  sceneId: string
  version: string
  title: string
  status: 'published' | 'disabled'
  summary: string
  capabilities: string[]
  inputs: SceneField[]
  outputs: SceneField[]
  workflow: SceneStep[]
  qualityRules: QualityRuleSummary[]
  presentation: PresentationSummary
  validation: ValidationSummary
}
```

首期不把 `draft` 和 `validating` 暴露为可编辑状态；原型中的状态用于后续发布流程。若场景依赖的 OGE 服务或模型连接不可用，详情页显示阻塞原因并禁用“创建任务”。

## 9. FastAPI 业务架构

### 9.1 分层与依赖

依赖方向固定为：

```text
api → application → domain
                    ↑
agent / jobs / integrations / persistence 实现 domain 定义的接口
```

业务模块：

| 模块 | 核心对象 | 职责 |
| --- | --- | --- |
| Projects | Project、Event、AOI | 项目、事件和空间范围 |
| Threads | Thread、Message、Run、TraceEntry | 用户任务线程、Agent 运行和审计投影 |
| Scenes | SceneVersion、Skill | 场景发现、版本与约束 |
| Settings | ModelConnection、ModelCatalogEntry、CredentialRef、ConnectionCheck | 多连接、默认模型、脱敏凭据和连接诊断 |
| Tasks | Task、TaskStep、RemoteJob | 确定性任务和 OGE 状态 |
| Results | ResultSet、Layer、Metric | 成果版本与结构化事实 |
| Artifacts | Artifact | 可在前端工作区打开的视图 |
| Inspections | InspectionItem、Feedback | 核查对象和人工反馈 |
| Reports | Report | 从指定成果版本生成报告 |
| Memory | MemoryEntry | 项目设置与经确认的案例摘要 |

### 9.2 线程、运行与任务的区别

- `Thread` 是用户持续工作的容器；
- `Run` 是一次 Agent 循环，可完成、失败、等待确认或等待外部任务；
- `Task` 是确定性业务工作流，不依赖模型存活；
- 一个 Run 可以查询多个对象，但只有确认后才能创建正式 Task；
- Run 等待 OGE 时保存检查点并结束当前执行占用，由任务事件触发恢复。

### 9.3 本地持久化

首期 SQLite 使用 WAL 模式，保存结构化元数据和追加式事件；大文件存入应用数据目录。

```text
<app-data>/
├── kunyu.db
├── artifacts/<artifact-id>/
├── results/<result-set-id>/
├── exports/
└── logs/
```

数据库不保存大型 GeoTIFF、PNG 或报告文件内容，只保存路径、类型、大小、空间参考、版本和来源。几何首期保存为 GeoJSON/WKB 与范围字段；复杂空间运算继续由 OGE 完成。

非秘密运行设置按命名字段保存到 SQLite，并带 `updated_at`。密钥按 `model_connection_id` 或 `oge_profile_id` 写入操作系统凭据库；数据库最多保存 `CredentialRef` 的类型、是否配置和更新时间。

线程保存最近一次 `ModelSelection` 只用于输入框预填。Run 创建时保存不可变的 `RunModelSnapshot`，包含连接 ID、Provider 类型、Base URL、模型 ID、推理强度和连接配置版本，但不保存密钥。Task 创建时保存 OGE Profile 与 SceneVersion 快照；后续修改或删除设置不改变已完成记录。

## 10. 自研最小 DSH

### 10.1 定位

`dsh` 是业务无关的最小 Agent Harness。它只解决五件事：

1. 安装和管理插件；
2. 注册并解析能力；
3. 以类型事件记录会话事实；
4. 推进模型—工具循环；
5. 在确认、外部任务或失败处暂停并恢复。

项目、地图、OGE、GeoSkill 和报告均属于 `kunyu` 插件或业务服务，不进入 DSH 核心。

### 10.2 从 DeepSeek Harness 借鉴与不借鉴的内容

| 借鉴 | 本项目实现方式 |
| --- | --- |
| everything is a plugin | 模型、工具、上下文、Skill、Memory、策略和事件存储通过能力接口装配 |
| capability seams | 插件只依赖声明的 Protocol，不互相导入具体实现 |
| typed events | Pydantic 判别联合定义事件，SQLite 追加保存 |
| recoverable session log | Reducer 从事件重建 RunState，等待任务后可恢复 |
| lifecycle | `install → start → stop`，按显式顺序装配和逆序关闭 |

首期不实现 Cordis、动态 npm 插件、热重载、远程插件市场、复杂扩展点继承和通用多 Agent 调度。

### 10.3 核心契约

DSH 按能力接缝拆分模块，不把所有 Protocol、数据类型和执行逻辑堆入单一 `contracts.py`。这些模块只定义业务无关的契约和最小运行机制，不包含坤舆的具体工具、记忆或地理业务规则。

| 模块 | 职责 |
| --- | --- |
| `agent.py` | `AgentRuntime`、运行输入输出与暂停结果 |
| `capabilities.py` | 插件生命周期、能力键与 Host 注册规则 |
| `model.py` | 模型请求、流式响应、Tool Call 和 Adapter 契约 |
| `tools.py` | Tool Schema、注册、调用与结果类型 |
| `context.py` | 请求上下文组装契约与预算 |
| `memory.py` | 记忆查询和候选写入契约；不实现业务记忆 |
| `policy.py` | 工具准入、副作用分级和用户确认决策 |
| `events.py` | 可追加的类型事件 |
| `event_store.py` | 事件追加、读取与顺序保证契约 |
| `runner.py` | 模型—工具循环与暂停、恢复控制 |
| `reducer.py` | 从事件确定性重建 `RunState` |

Tool 和 Memory 都分为“框架契约”与“业务实现”两层：`dsh.tools` 与 `dsh.memory` 定义接口，`kunyu.agent.tools` 与 `kunyu.agent.memory` 实现地理业务能力。事件日志及 Reducer 解决运行恢复，不代替 Thread Summary、Project Memory 和 Case Memory。

```python
class Plugin(Protocol):
    manifest: PluginManifest

    def install(self, host: Host) -> None: ...
    async def start(self) -> None: ...
    async def stop(self) -> None: ...


class Host(Protocol):
    def provide(self, key: CapabilityKey[T], value: T) -> None: ...
    def require(self, key: CapabilityKey[T]) -> T: ...
    async def emit(self, event: AgentEvent) -> None: ...


class Tool(Protocol):
    spec: ToolSpec

    async def invoke(self, context: ToolContext, arguments: BaseModel) -> ToolResult: ...
```

实现约束：

- 插件列表在 `kunyu.agent.bootstrap` 中显式声明，不扫描任意目录；
- 每个能力键只能有一个默认提供者，重复注册立即启动失败；
- Manifest 只包含 `id`、`version`、`requires`、`provides` 和配置 Schema；
- DSH 使用 Protocol 和 Pydantic，不依赖 FastAPI、SQLAlchemy、OGE SDK 或前端类型；
- 插件启动失败时整体启动失败，不静默降级为其他实现；
- 设置页可以增删 `ModelConnection`，但只能使用代码已装配的 Provider 适配器；不能增删插件、改变 Capability 依赖或绕过 PolicyGate；
- 模型连接、模型 ID 与推理强度在新 Run 开始时解析并形成快照，进行中的 Run 不热切换，也不在连接失败时自动改用其他连接。

### 10.4 首期插件

| 插件 | 提供能力 |
| --- | --- |
| `event_store.sqlite` | 追加事件、按线程读取事件 |
| `model.router` | 校验 ModelSelection、解析连接并创建 RunModelSnapshot |
| `model.openai_compatible` | DeepSeek/OpenAI Compatible 的流式响应与 Tool Call |
| `model.ollama` | 已配置本地 Ollama 连接的流式响应与 Tool Call |
| `context.kunyu` | 项目、地图、Skill、Memory 和运行摘要 |
| `tools.kunyu` | 业务 Tool Registry |
| `skills.geo` | GeoSkill 查找与版本加载 |
| `memory.project` | 项目记忆查询和候选写入 |
| `policy.kunyu` | 权限、副作用、预算和确认门禁 |

这些插件由团队实现并随源码交付。OGE 不作为模型插件直接挂载；它只能通过 `tools.kunyu` 调用应用服务。

### 10.5 类型事件

所有可恢复状态来自追加式事件：

```json
{
  "event_id": "evt_01",
  "thread_id": "thr_01",
  "run_id": "run_01",
  "sequence": 12,
  "type": "tool.completed",
  "occurred_at": "2026-09-20T08:00:00Z",
  "payload": {}
}
```

首期事件集合：

- `thread.created`
- `message.user.appended`
- `run.created`
- `run.model_selected`
- `message.assistant.delta`
- `message.assistant.completed`
- `plan.proposed`
- `confirmation.requested`
- `confirmation.resolved`
- `tool.requested`
- `tool.started`
- `tool.completed`
- `tool.failed`
- `run.waiting_external`
- `run.resumed`
- `artifact.published`

- `run.failed`
- `run.cancelled`

事件中不保存模型隐藏推理；工具输入只保存校验后的结构化参数和脱敏摘要。

### 10.6 Run 状态机

```mermaid
stateDiagram-v2
    [*] --> ready
    ready --> model_running
    model_running --> waiting_confirmation: 请求有副作用的工具
    waiting_confirmation --> tool_running: 用户批准
    waiting_confirmation --> cancelled: 用户拒绝并结束
    model_running --> tool_running: 允许的只读工具
    tool_running --> model_running: 同步结果
    tool_running --> waiting_external: 创建长任务
    waiting_external --> model_running: 收到任务结果事件
    model_running --> completed: 形成最终回复
    model_running --> failed
    tool_running --> failed
    completed --> [*]
    failed --> [*]
    cancelled --> [*]
```

Runner 的最小循环：

1. 校验输入中的 `ModelSelection`，创建 Run 与不可变 `RunModelSnapshot`；
2. 追加用户消息并由 Reducer 重建当前 RunState；
3. Context 插件按预算组装上下文；
4. Model Router 按快照选择唯一 Adapter，模型返回文本增量、Tool Call 或最终回复；
5. Tool Call 先经 Schema 校验和 PolicyGate；
6. 需确认则写事件并暂停；只读工具直接执行；
7. 长任务返回 `task_id` 后写等待事件并释放运行；
8. 任务完成事件恢复 Run，读取成果摘要；
9. 写最终消息和完成事件，并更新线程的最近模型选择。

每次 Run 限制模型轮次、工具次数、墙钟时间和模型用量。达到限制后返回可解释的失败状态，不进行无限循环。

### 10.7 装配方式

最小 DSH 采用一个代码入口完成确定性装配：

```python
def build_geo_agent(services: ApplicationServices) -> AgentRuntime:
    return AgentRuntime(
        event_store=SqliteEventStore(...),
        model=ModelRouter(
            connections=services.model_connections,
            credentials=services.credentials,
            adapters={
                "openai_compatible": OpenAICompatibleAdapter(),
                "ollama": OllamaAdapter(),
            },
        ),
        context=KunyuContextProvider(...),
        tools=KunyuToolRegistry(...),
        skills=GeoSkillResolver(...),
        memory=ProjectMemoryProvider(...),
        policy=KunyuPolicyGate(...),
    )
```

该入口是系统 Composition Root，也是赛事展示“自研 Harness 如何组装能力”的直接证据。首期不建立 `AgentDefinition` 数据表，不把插件列表序列化到数据库，也不提供对应 CRUD API。设置页管理的是 `ModelConnection`、OGE Profile 和其他运行参数，GeoSkill 页面管理的是 `SceneVersion`；这些对象都不等于 Agent 装配。

## 11. GeoSkill、Tool 与 Memory

### 11.1 GeoSkill

GeoSkill 是版本化场景契约，不是散装提示词：

```text
backend/scenarios/flood-assessment/
├── manifest.yaml
├── SKILL.md
├── workflow.yaml
├── validation.yaml
├── presentation.yaml
├── references/
└── examples/
```

- `manifest.yaml`：场景 ID、版本、输入输出、工具和算法能力依赖；
- `SKILL.md`：数据选择、处理策略、质量限制和解释规则；
- `workflow.yaml`：确定性步骤、依赖、条件分支和参数映射；
- `validation.yaml`：输入、观测覆盖和成果完整性规则；
- `presentation.yaml`：计划字段、图层样式、统计列和报告字段。

发布后不可原地修改；任务锁定场景版本与具体 OGE 服务绑定。

场景包启动加载流程固定为：发现内置目录 → 校验文件和 Schema → 解析能力依赖 → 检查 OGE 服务绑定 → 生成只读页面投影 → 登记可用版本。任何一步失败都将该版本标为不可用并记录明确原因，不以缺字段默认值继续运行。

GeoSkill 页面与 DSH 的关系是“选择契约”，不是“装配运行时”：

1. 用户查看已发布 SceneVersion 并创建线程；
2. Thread 保存默认 `scene_version_id`，用户可在正式 Task 创建前更换；
3. DSH Context Provider 读取该版本的精简约束，辅助形成计划；
4. `workflow.preview` 按 Schema 生成确定性计划快照；
5. 用户确认后，`workflow.submit` 由应用服务创建 Task 并锁定版本；
6. 后续 Run 只能读取 Task 已锁定的场景版本，不能通过对话篡改。

后续 GeoSkill 编辑器若实现，发布过程必须新建版本、完成 Schema 校验和至少一个验证案例，再原子地将版本标为 `published`。已发布目录不可直接覆盖。

### 11.2 Tool

首期工具保持精简：

```text
project.get_context
scene.get
data.search_observations
data.describe_observation
workflow.preview
workflow.submit
task.get
result.get_summary
result.query_features
inspection.update
report.create
```

副作用分级：

| 等级 | 类型 | 示例 | 策略 |
| --- | --- | --- | --- |
| L0 | 本地读取 | 项目、场景、已有成果 | 自动执行 |
| L1 | 外部只读 | OGE 产品、影像、任务状态 | 自动执行并记录 |
| L2 | 创建或修改 | 提交 OGE 任务、保存核查、生成报告 | 每次明确确认 |
| L3 | 删除或发布 | 删除成果、发布场景、修改凭证 | 不向首期 Agent 开放 |

Tool 只能调用应用服务。模型不能提交 URL、SQL、Python 代码、服务器路径或 OGE 原始请求。

### 11.3 Memory

首期只实现三层：

| 类型 | 内容 | 写入规则 |
| --- | --- | --- |
| Thread Summary | 当前目标、已确认选择、等待事项 | 每次 Run 完成后生成并保存来源 |
| Project Memory | 常用区域、资产、关注对象和报告设置 | 用户明确保存或确定性业务操作产生 |
| Case Memory | 已完成任务、质量和人工复核摘要 | 从正式成果和核查记录生成 |

方法知识保存在版本化 GeoSkill 中，不额外建设向量知识库。首版按项目、场景、类型、时间和关键词检索 SQLite 记录。

## 12. OGE 集成

### 12.1 两条开发链路

OGE 文档体现两种不同链路，架构中必须分开：

1. **算法开发链路**：遥感人员在 OGE 开发环境用 `Service.getCoverage`、`getCoverageCollection`、`getProcess(...).execute(...)`、样式和导出能力开发脚本，并发布为 OpenAPI 算子或组合模型。
2. **应用调用链路**：本地 FastAPI 只调用已发布 OpenAPI，管理鉴权、参数映射、异步 `processId`、结果读取和业务成果登记。

React 和 DSH 都不直接运行 OGE Python 脚本。

### 12.2 鉴权

OGE 存在双轨凭证：

- JWT：登录、上传、资产列表、产品/影像、算子定义、结果和下载；
- AppKey `tk`：调用 `/openapi/**` 已发布服务；部分 OpenAPI 状态查询场景也可能要求 `tk`。

手册不同位置对登录密码处理和状态查询凭证存在表述差异，不能把未经联调的假设写死。`OGEAuthProfile` 按实际环境记录登录请求形式、状态查询鉴权和网关前缀；联调结果作为配置与接入文档的一部分。

### 12.3 输入引用

适配层支持手册定义的引用并保存原始引用类型：

- `Personal:MyData:myData/{文件名}`
- `Personal:Asset:{assetUuid}`
- `Personal:Process:{processId}`
- `Platform:Coverage:{imageIdentification}:{productName}`
- `Platform:Product:Coverage:{productName}:{imageIds}`
- `Platform:Product:{productName}`

前序 OGE 结果优先使用 `Personal:Process:{processId}` 在平台内部衔接，避免无意义的下载再上传。

### 12.4 OGE Adapter

```python
class OGEClient(Protocol):
    async def list_products(self, query: ProductQuery) -> list[Product]: ...
    async def list_images(self, product_id: str) -> list[Observation]: ...
    async def describe_process(self, name: str) -> ProcessDefinition: ...
    async def submit_algorithm(self, request: AlgorithmRequest) -> RemoteJob: ...
    async def submit_combination(self, request: CombinationRequest) -> RemoteJob: ...
    async def get_job(self, process_id: str) -> RemoteJobStatus: ...
    async def get_result(self, process_id: str) -> RemoteResult: ...
    async def download_result(self, process_id: str, target: Path) -> DownloadedAsset: ...
```

适配层统一处理：

- Base URL、网关前缀、JWT 刷新和 `tk` 注入；
- OGE `code/msg/data` 与 HTTP 状态的双重校验；
- `resultStatus` 和引擎状态到内部状态的映射；
- 输出文件名唯一性；
- 限流、超时、可重试错误和脱敏日志；
- `processId`、输入引用、算法版本与内部步骤关联；
- TIFF、GeoJSON、JSON、COG 预览和下载结果的校验。

### 12.5 持久任务监督器

首期不用 Celery。FastAPI lifespan 启动一个任务监督器：

1. 从 SQLite 领取到期的 `TaskStep`；
2. 首次执行时提交 OGE 并立即保存 `processId`；
3. 按 `next_poll_at` 查询状态，不阻塞请求线程；
4. 成功后登记结果，失败后保存分类错误；
5. 在同一事务内写业务状态和待发布事件；
6. 通过内部事件恢复等待中的 DSH Run；
7. 进程重启后扫描 `submitted/running` 步骤继续查询。

“取消”只停止尚未提交的后续步骤；OGE 已受理作业若没有可靠取消接口，则继续跟踪并明确显示状态。

## 13. 核心数据模型

```mermaid
erDiagram
    PROJECT ||--o{ THREAD : contains
    PROJECT ||--o{ EVENT : contains
    SCENE ||--o{ SCENE_VERSION : versions
    SCENE_VERSION ||--o{ SCENE_VALIDATION : verifies
    THREAD ||--o{ MESSAGE : contains
    THREAD ||--o{ AGENT_RUN : executes
    THREAD ||--o| THREAD_PREFERENCE : remembers
    AGENT_RUN ||--o{ AGENT_EVENT : records
    AGENT_RUN ||--o{ CONFIRMATION : requests
    AGENT_RUN ||--|| RUN_MODEL_SNAPSHOT : uses
    MODEL_CONNECTION |o--o{ RUN_MODEL_SNAPSHOT : source
    AGENT_RUN }o--o{ TASK : links
    TASK ||--o{ TASK_STEP : contains
    TASK_STEP ||--o| REMOTE_JOB : submits
    TASK ||--o{ RESULT_SET : produces
    RESULT_SET ||--o{ ARTIFACT : presents
    RESULT_SET ||--o{ CITATION : supports
    RESULT_SET ||--o{ INSPECTION_ITEM : derives
    MESSAGE ||--o{ CITATION : contains
    SCENE_VERSION ||--o{ TASK : defines
```

关键约束：

- Task 创建后锁定输入、GeoSkill 版本和 OGE 服务绑定；
- ResultSet 不覆盖更新，复算产生新版本；
- Artifact 只引用确定的资源和成果版本；
- 定量结论必须关联 Citation；
- Confirmation 保存操作摘要、参数摘要、决定人和时间；
- RemoteJob 保存 `processId`、鉴权 Profile 标识和最近查询状态，不保存凭证；
- AgentEvent 以 `(run_id, sequence)` 唯一并只追加；
- SceneVersion 发布后不可变，SceneValidation 保存验证用例、结果和时间；
- ModelConnection 使用稳定 ID，数据库通过唯一约束保证最多一个启用的默认连接；
- ThreadPreference 只记录下一次输入框预填值，不决定已创建 Run 的模型；
- RunModelSnapshot 保存连接 ID、Provider、Base URL、模型 ID、推理强度和配置版本，不保存任何密钥；
- CredentialRef 不是业务实体，只表示系统凭据库中某类凭据是否已配置。

模型相关契约：

```ts
interface ModelConnection {
  connectionId: string
  displayName: string
  providerType: 'openai_compatible' | 'ollama'
  baseUrl: string
  isDefault: boolean
  enabled: boolean
  configVersion: number
  credential: { configured: boolean; updatedAt: string | null }
  lastCheck: { status: 'ok' | 'failed' | 'unchecked'; checkedAt: string | null }
}

interface ModelSelection {
  connectionId: string
  modelId: string
  reasoningEffort: 'standard' | 'high'
}

interface RunModelSnapshot extends ModelSelection {
  providerType: ModelConnection['providerType']
  baseUrl: string
  connectionConfigVersion: number
}
```

### 14.2 SSE 外壳

```json
{
  "event_id": "evt_01",
  "event_type": "artifact.published",
  "occurred_at": "2026-09-20T08:00:00Z",
  "thread_id": "thr_01",
  "run_id": "run_01",
  "sequence": 18,
  "payload": {}
}
```

客户端使用最后一个 `event_id` 重连；服务端按序补发。SSE 是 DSH/Task 事件的展示投影，不把内部调试信息或模型隐藏推理暴露给前端。

## 15. 可信、安全与可观测性

### 15.1 可信表达

以下内容必须带 Citation：面积、比例、日期、排名、图斑、任务状态和空间关系。Citation 可指向指标字段、输入观测、任务步骤或空间对象。出现下列情况时只允许输出“观测不足”“结果冲突”或“需要人工核查”：

- OGE 作业未完成或失败；
- 有效覆盖不足；
- 输入、场景或成果版本不明确；
- GeoSkill 未定义该结论；
- 多源结果冲突且无人复核。

### 15.2 安全

- 用户文本、GeoSkill、Memory、资产元数据和工具结果都视为不可信内容；
- Tool 参数必须由 Pydantic 校验，并只能引用当前项目允许的资源；
- DSH PolicyGate 在工具执行前检查权限、副作用、预算和确认快照；
- Agent 不拥有 OGE 和模型密钥；
- 普通日志不记录密码、JWT、AppKey、session token、完整模型上下文和大文件内容；
- 文件导入检查类型、大小和解析结果，业务服务决定落盘位置；
- 删除、覆盖和场景发布不向首期 Agent 开放。

### 15.3 可观测性

使用统一关联链：

```text
thread_id → run_id → event_id → tool_call_id → task_id → task_step_id → oge_process_id → result_set_id → artifact_id
```

首期记录：

- Electron 后端启动耗时、异常退出和健康状态；
- API 延迟、错误码和 SSE 重连；
- Run 首响应时间、模型轮次、工具次数和确认等待；
- OGE 提交、排队、运行、结果读取和错误分类；
- Artifact 创建、打开和引用定位；
- 任务恢复次数和成果校验失败原因。

可观测日志与用户轨迹不是同一接口。内部日志可包含堆栈、重试原因和性能字段，但必须脱敏且只写本地日志；`TraceEntry` 是面向用户的稳定产品投影，只包含可解释动作、状态、耗时、资源引用和错误摘要。任何模型隐藏推理都不得进入二者的产品展示层。

## 16. 开发顺序

### 阶段一：桌面骨架与线程

1. 建立 `electron/`、`frontend/`、`backend/`；
2. Electron 拉起 FastAPI，完成 Ready、健康检查和关闭；
3. 实现项目、线程、消息、SQLite 迁移和 SSE；
4. 完成 Codex 式可收起侧栏和 `概览 | [对话↔轨迹] | 地图` 路由；
5. 实现对话活动行、轨迹投影和地图轻量输入框，验证切换后上下文不丢失。

验收：双击启动后可创建线程、发送消息、退出并恢复，不需要手动启动后端。

### 阶段二：最小 DSH

1. 实现 Host、Plugin、Capability、Event、Reducer 和 Runner；
2. 接入 Model Router、OpenAI Compatible Adapter、Tool Registry、Context 和 PolicyGate；
3. 实现确认快照、内联活动、轨迹投影和运行恢复；
4. 实现 GeoSkill 只读目录、版本详情与 `SceneVersion` 选择；
5. 先用确定性的本地读取工具验证循环，不创建 OGE 任务。

验收：一次 Run 可在只读 Tool、待确认和完成状态之间正确流转，重启可重建状态。

### 阶段三：OGE 真实链路

1. 完成独立设置 Shell、系统凭据库、多模型连接、模型选择与 OGE 连接测试；
2. 完成 OGE Profile、双轨鉴权和产品/影像发现；
3. 发布并联调洪涝脚本或组合模型；
4. 实现任务监督器、`processId` 恢复和成果校验；
5. 完成任务、地图和统计 Artifact。

验收：一个真实 OGE 任务从确认、提交、等待到结果展示完整运行。

### 阶段四：洪涝纵向示例

1. 完成洪涝 GeoSkill、工作流、校验和展示定义；
2. 形成榕江县输入数据与可重复任务；
3. 加入 Citation、核查清单和 Markdown 报告；
4. 打磨观测不足、失败、重试和应用重启场景。

验收：完成第 4 章全部示例状态，并能作为赛事演示主线。

### 阶段五：再决定扩展

主链稳定后，再根据演示价值选择 GeoSkill 编辑发布、灾后植被状态跟踪、三维 Artifact、服务器部署或 PostgreSQL/Worker 拆分，不并行铺开。Agent 自由装配页不在该扩展列表中；只有出现至少两个经过验证的运行角色时，才评估受控 `AgentProfile`。

## 17. 首期完成定义

首期只有同时满足以下条件才算完成：

- Electron 自动拉起并管理 FastAPI，普通用户不操作终端；
- Agent 任务线程构成应用主界面；
- 概览、分析和地图三个一级视图共享同一 Thread 状态，对话/轨迹切换不丢上下文；
- 轨迹能解释 Agent、Tool、Task 和 Artifact 状态，但不暴露隐藏推理；
- 地图以完整工作区打开，切换前后保持视口、图层、空间选择和输入草稿；
- DSH 核心由团队自主实现，边界、源码和事件可说明；
- GeoSkill 页面能查看已发布版本、校验状态并基于指定版本创建任务；
- 设置页能管理多个模型连接、唯一默认连接和 OGE 接入，任何读取接口都不返回凭据明文；
- 输入框可以选择连接、模型和推理强度，Run 保存不可变模型快照且失败时不自动改用其他连接；
- 计划、确认、Tool、等待外部任务和恢复形成完整事件链；
- 后端通过真实 OGE OpenAPI 执行至少一个已发布洪涝服务；
- 线程、任务和成果在应用重启后恢复；
- 地图、统计、核查和报告共享同一成果版本；
- Agent 的定量结论均有可点击引用；
- FastAPI 可独立运行并提供完整案例的 WebService；
- 凭证不进入 Renderer 持久化、Agent 上下文、SSE 或普通日志。

## 18. 尚未冻结的产品决策

以下内容不阻塞架构和首个示例，可在第一版可交互原型后确定：

1. 概览页首屏最终展示哪些成果与记忆摘要；
2. 线程列表是否同时按项目和灾害事件分组；
3. 最终预置哪些模型 Provider 与模型目录；
4. 系统凭据库在目标 Windows/macOS 打包环境的支持矩阵；
5. 桌面发布优先支持 Windows 还是同时支持 macOS；
6. 地图顶部的 3D 入口是首期可用能力还是禁用占位；
7. GeoSkill 编辑发布是否进入赛事演示，还是只展示只读目录；
8. 服务器部署是否需要在首期与桌面包同时交付。

现有 v3 原型已经冻结页面职责和主视觉方向。阶段一应优先做可点击壳层，验证嵌套模式切换、轨迹投影、地图上下文保持、多模型 Run 快照、GeoSkill 到任务的入口和设置反馈；视觉细节可继续调整，但不得改变 `Project → Thread → Run → Artifact` 核心模型或把 Agent 装配暴露为用户配置。
