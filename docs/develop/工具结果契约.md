# 工具结果契约

每个工具继承 `BaseTool`，显式声明 `ToolOutputContract` 的三个投影。注册时检查契约，执行时校验投影结果；遗漏任何通道都属于实现错误。

| 接口 | 消费者 | 应保留的内容 |
| --- | --- | --- |
| `agent_result` | 正常 Agent 请求 | 完成下一步所需的事实、引用、参数约束、续读位置，以及明确授权的图片收据 |
| `frontend_result` | 对话和轨迹的结果展示 | 用户可理解的文字、图片、文件差异、任务进度或地图回执；不直接显示内部协议 JSON |
| `compact_result` | 折叠标题和上下文压缩 | `summary` 是简短的人类可读摘要；`content` 是供压缩模型读取的精简事实，保留结果引用、错误、参数约束和续读位置 |

`execute` 返回 `ToolResult(content, result, events)`。`content` 是工具明确构造的 Agent 内容，`result` 保留结构化业务数据；三种投影分别处理该执行结果。常用的 `agent_content` 策略原样保留工具构造的内容，工具也可以声明自己的 Agent 投影。

```python
class ExampleTool(BaseTool):
    output_contract = ToolOutputContract(
        agent=agent_content,
        frontend=example_display,
        compact=example_compact,
    )
```

工具按自身语义选择投影，相关实现放在 `agent/tools/outputs/` 的职责模块中。一个工具类承载多种操作时，必须逐一选择契约。MCP 接入使用显式的外部工具策略：展示文本和图片收据，压缩时保留未知语义的文本，不猜测哪些业务字段可以删除。

前端只按展示契约的 `kind` 选择通用渲染器，不按工具名、名称前缀或 Agent 文本猜测结果。已有的 `text`、`code`、`read`、`search`、`file_change`、`image_read`、`images`、`todos`、`analysis`、`map`、`subagent`、`none` 可直接复用。只有引入新的视觉类型时才扩展渲染器。工具文案与投影结构分离，文案集中在 `agent/prompts/tool-views.yaml`。

三种投影随 `tool.completed` 事件一起提交，并写入工具调用快照。刷新和历史回放读取已保存的投影，不重新执行工具。完整协议数据仍可在轨迹详情查看。

压缩只替换被选中旧历史中的成功工具结果，最近保留区继续使用原始 Agent 内容；工具调用和结果保持配对。不能用前端文案替代模型事实，也不能截断 JSON 字符串冒充有效压缩结果。文件工具保留路径和续读位置，算子定义保留完整参数约束并省略示例代码，图片保留收据并明确标注像素已省略。

数据库基线为版本 6，完整结构保存在 `backend/src/kunyu/persistence/schema.sql`。版本 5 的记录在一次事务中补齐展示和压缩投影；迁移失败则整体回滚，不在运行时兼容或猜测旧结果格式。
