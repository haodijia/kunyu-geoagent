# 地图与 Agent 连续会话：最终设计方案

更新：2026-10-16。本方案纳入用户关于通用异步执行框架的纠正：后台执行、等待和续接由框架承担，模型工具清单不新增任务等待工具。本轮仅更新设计文档，未修改业务代码；先前交互原型只用于讨论视觉，实际时序以本文为准。

## 1. 产品约定

- **session 是唯一会话。** 对话页和地图页共享消息、草稿、选择、审批与任务；地图页是同一会话的空间操作界面。
- **Agent 用工具决定展示。** 检索成功只产生数据。Agent 需要让用户选景时，显式调用地图展示工具，打开当前会话的地图、定位并展示候选；前端不能根据“检索完成”自行切页。
- **长工具由通用运行器托管。** 服务持续运行；框架最多等待 240 秒后可以让出控制权，将 running 状态交给上下文组装器。模型自然解释，框架继续等待并在完成后自动续接；模型无需调用等待或轮询工具，同一服务不重新提交。
- **地图展示保持轻量。** 全幅地图、底部逐行渐隐消息、同一个输入框、必要的候选/成果操作区与任务状态条。

## 2. 完整业务流程

| 步骤 | Agent / 工具 | 用户界面 |
| --- | --- | --- |
| 新建会话 | 接收“查询卫星影像”及已有区域、时间条件；缺少必要条件时询问 | 普通对话页，保留当前输入习惯 |
| 检索影像 | `oge_search_images` 返回一组持久候选及元数据 | 显示真实检索过程；检索本身不导航 |
| 邀请选景 | Agent 调用 `map_present`，目标为候选集，要求打开地图、定位并供用户选择 | 当前 session 切到地图，显示覆盖范围与候选；输入框和草稿保持 |
| 用户选择 | 点选仅预览；“使用此景”或“第二景，计算 NDVI”提交明确选择 | 所选影像高亮，输入区显示对象标签；已明确选择不再重复追问 |
| 发起计算 | 后端冻结影像、区域与参数；Agent 调用 `oge_calculate_ndvi`，复用已有审批 | 原位置承接审批与任务状态，无新增确认弹窗 |
| 异步等待 | 通用执行器托管已提交的工具执行，等待最多 240 秒；未完成时将执行身份、running 及已知状态放入上下文 | 显示真实阶段与耗时；模型根据真实状态自然回答 |
| 自动续接 | 模型本步回答结束后，运行器发现未结束执行，自动进入等待；完成、新输入或下一窗口到期时继续组装上下文 | 地图与输入仍可操作；普通文字淡出，任务状态保留，无需模型额外调用等待工具 |
| 展示成果 | Agent 获取成功成果后调用 `map_present`，目标为成果并要求上图 | 添加图层、定位及成果操作；展示结果进入模型上下文，随后解释 |
| 继续交互 | 新指令携带所选影像、对象、图层或任务引用，调用对应工具 | 调透明度、查看来源、选择范围或继续分析，全程留在该 session |

## 3. 工具边界

下列为目标契约；`map_present` 及通用异步托管语义需要实现，不是当前已存在的完整能力。工具声明自己的业务执行及托管能力，等待窗口、调度与续接属于运行器。

| 工具 | 职责 | 返回内容 |
| --- | --- | --- |
| `oge_search_images` | 按区域、时间等条件检索并保存候选集 | candidate_set_id、稳定编号、影像 ID 与已知元数据 |
| `map_present` | 显式打开当前会话地图、展示指定候选或成果，按指令定位；候选可进入选择交互 | 展示请求 ID、目标引用、当前可核实的展示状态 |
| `oge_calculate_ndvi` | 登记一次提交并发起服务，将其生命周期交给框架托管 | 业务任务身份与可跟踪的执行；阶段状态、终态结果由框架统一投递 |
| 现有地图查询/样式工具 | 读取地图上下文、修改图层显隐、透明度和顺序等 | 实际应用的地图版本与状态 |

`map_present` 通过受限的目标类型引用候选集或成果，不接收任意路由、URL 或前端脚本。页面切换、展示内容、空间定位均来自工具的明确指令；工具可将相关动作合成一次调用，减少不必要的往返。

候选展示与计算成果展示共用同一个工具入口，分别使用明确的参数类型；地图数据与渲染实现仍按职责分层。现有低层地图能力按实际用途整理，替换的旧入口完整删除。

## 4. 异步工具与模型循环

### 4.1 两种生命周期

**托管执行**属于通用 Agent 运行层，保存执行身份、原调用身份、归属、状态及恢复方式。只有明确支持托管和恢复的工具才能让出执行作用域，不能对任意超时工具一律转后台。OGE 适配器复用当前 AnalysisJob 及监督器，真实业务状态仍为 submitting、queued、running、collecting、succeeded、failed 或 submission_unknown；查询鉴权与连接状态独立记录，不再维护一套相同的 NDVI 作业状态。

**模型协议表示**与后台执行生命周期分开。普通同步工具协议在继续模型前需要匹配的阶段回执；回执可以说明后台仍运行，最终结果再通过有来源的完成通知进入上下文，不对同一调用重复发送结果。明确支持原生异步工具调用的协议则允许调用未返回时继续模型，随后按原 call_id 交付最终结果。各提供方按已声明、已验证的真实能力编码，不能一概认定所有协议都允许或都禁止未完成调用跨回合；这不改变框架统一托管执行的职责。

```text
调用计算工具 → 提交一次 → 框架托管执行并等待 ≤240 秒
  ├─ 成功：投递成果 → 模型调用地图展示工具 → 解释结果
  ├─ 失败：投递真实错误 → 模型解释或请求必要操作
  └─ 未完成：框架让出控制权，上下文加入 running 状态
       → 模型自然说明进度，本步回答结束
       → 运行器发现未结束执行，自动等待
       → 完成 / 新用户输入 / 下一等待窗口到期
       → 再次组装上下文并推进模型
```

240 秒是运行器交还控制权的等待窗口，不是服务失败、远端取消或总运行上限。模型不承担重复等待调用。正常阶段变化由后台监督器发布，不为每次轮询或每一秒计时唤醒模型。没有真实百分比时只展示已知状态和耗时。

### 4.2 运行时与上下文

- 首次提交使用原始调用身份去重；框架后续观察和等待始终绑定同一托管执行及业务任务。提交结果未知时保留 submission_unknown，不自动重新提交。
- 运行器区分“本次等待已返回”和“后台任务已完成”。正常让出控制权不能记作计算失败或成果成功；对话/轨迹的任务卡持续跟踪同一后台任务，等待记录归入该任务。
- 每次真正请求模型前，上下文组装器注入相关执行的真实快照：执行身份、输入引用、状态、开始时间、最近核查时间、阶段、成果或错误，以及当前地图/选择状态。来源和整数版本进入持久记录，历史请求可重建。
- 模型据真实上下文自行组织回答，不要求调用前固定说一句话，也不由前端伪造助手消息。模型说明仍在计算后，框架自动继续管理原执行；业务工具、系统提示及技能中不要求模型额外调用等待接口。
- 模型停止边界同时检查新用户输入、待完成执行与待消费通知。仍有活跃执行时进入可取消的等待状态，而不是把本步自然语言结束直接当作整个任务完成；不能伪造用户消息来维持循环。
- 等待释放活动执行资源，与模型活动时间预算分开；模型调用按真实预算计数。模型轮次结束或暂停不能改变远端任务的事实状态。
- 任务完成、失败或收到新用户输入可提前结束当前等待。普通进度更新只刷新界面。订阅和状态复查防止漏掉刚完成的任务；终态、窗口到期与用户输入合并后串行推进一个模型步骤。当前没有待执行模型轮次但保留了执行续接意图时，终态事件幂等进入该 session 的续接队列。
- 鉴权待处理、submission_unknown 和用户已停止的执行等待必要操作，不由定时器无效续跑。业务状态、UI 投影与模型通知分别表达，界面收到进度不等于模型已经收到。
- 用户停止 Agent 后，撤销该次自动续接意图；后台任务是否取消另行表达。界面仍能恢复任务状态，不能因服务完成擅自重启用户已停止的 Agent。

### 4.3 当前代码的改动点

当前 Runner 在 tool phase 中等待整个工具批次返回后才进入下一次模型请求；仅修改上下文组装器不会让模型在等待中获得执行机会。[Runner](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/runtime/runner.py:210)

当前 OGE 服务工具等待上限为 15 分钟，到期抛出 ANALYSIS_WAIT_TIMEOUT，而监督器继续工作。需要把等待与阶段状态投递提到通用运行层，OGE 工具只负责提交和业务生命周期绑定；不能简单把超时改为 4 分钟。[服务工具](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/tools/oge/service.py:30)

工具活动时间的预留、结算也需要区分实际执行与远端等待，避免合法的长任务消耗完活动时间切片。[工具执行器](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/runtime/runner_tools.py:248)

现有 turn_stopping hook 后只检查用户 next-step 输入，单纯注入 context 仍会结束 Run。需要补齐待执行通知判定、自动等待和安全续接；上下文组装器只负责描述事实，不承担调度。[停止边界](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/runtime/runner.py:194)、[输入判定](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/context.py:100)

### 4.4 Codex 对照与采用范围

OpenAI 官方 Codex 指南明确区分 exec_command 的长生命周期进程会话与 write_stdin 的续接读取，空输入可用于轮询输出。因此不能说 Codex 没有续接工具，也不能把界面上持续运行的一张工具卡等同于只有一次底层工具交互。[官方 Codex 指南](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)

官方异步工具文档也明确：应用仍负责后台执行；原生异步能力由特定模型和协议提供；应用可以在结果就绪后直接投递，等待工具只是可选控制方式。[官方异步工具文档](https://developers.openai.com/api/docs/guides/async-tool-calling)

本项目按用户要求采用框架自动等待与续接，不向模型暴露额外等待工具。借鉴 Codex 的执行持有、状态与结果分离，不宣称本项目自动调度方案与 Codex 的模型侧续接接口完全相同。通用能力需要执行框架实际实现，不能由一个 Python async 函数或上下文注入自动获得。

## 5. 地图页面与动态视觉

继续参考本地 Mu 的中性色、细边框、浅紫主操作和紧凑过程行，复用现有 shadcn/ui、SessionComposer、AgentControls 与消息内容投影。轨迹沿用 deepseek-harness 已采用的事实事件与多视图投影方式，不建设第二套地图聊天服务。

| 区域 | 设计 |
| --- | --- |
| 主画布 | 地图占主视觉，承载影像覆盖范围、所选对象、成果图层 |
| 临时对象区 | 候选列表与成果详情使用同一个紧凑区域；选择完成后收起候选，保留所选影像标签 |
| 底部消息带 | 与输入框对齐，默认显示最近 3 个视觉行；普通文字不用大气泡或独立卡片 |
| 任务/操作位 | 保留真实运行状态、待选择、待审批、待回答和错误；直到处理后收起 |
| 输入框 | 始终是同一份草稿与发送机制，支持直接回复“第二景”“运行 NDVI”和后续问题 |
| 历史 | 在底部区域向上展开完整对话，最多约占地图高度 45%；完整轨迹继续从已有入口查看 |

### 消息流动效

- 当前生成的行保持清晰，新行出现时，旧行以约 240–280ms 向上移动；较旧两行依次弱化到约 65%、30%，顶部通过渐变退出。
- 按真实容器换行计数，token 更新当前行，不为每个 token 重播动画；流式输出结束后停留约 10 秒，再逐行淡出。
- 悬停消息、键盘阅读和展开历史时暂停渐隐；阅读历史时停止自动跟随，新消息用轻提示承接。恢复时展示最新内容，不补播积压动画。
- 待选择、审批、问题、运行任务和错误不参与普通文字淡出。历史消息完整保存；减少动态效果模式下直接更新。
- 输入框不随消息行数跳动；文字附近使用柔和背景渐变保证可读性，地图其余区域保持清晰。无障碍播报只关注新内容和关键状态，不播报透明度及每秒计时。

## 6. 选择、展示与用户控制

**选景一致性。** 每次检索形成固定候选集和编号，点选、覆盖范围与“第二景”指向同一个对象。后端校验 session 归属与版本，提交时冻结影像、AOI 和参数。运行中修改地图或选择只影响后续操作，成果明确标明实际输入。

**导航由工具驱动。** 只消费当前会话中新发布的地图工具展示请求；按 request_id 处理一次。历史恢复、SSE 重连、后台任务完成都不能自行触发导航。若存在明确的新工具请求，可执行对应切换；当前已处于地图时就地展示。

**相机与焦点。** 工具可以要求定位。用户正在拖图或编辑时，先展示内容并承接定位请求，避免中途打断操作；保留“定位结果”入口。不强制聚焦输入框、不清空草稿、不持续追踪覆盖用户相机。

**成果与展示分别记录。** 计算成功只说明成果可用；Agent 再调用地图展示工具。前端记录展示请求与当前画布可核实的状态；加载失败时保留“计算完成、地图显示失败”及重试动作，Agent 据工具返回信息解释，不提前声称已经显示。

**停止语义明确。** “停止等待”“停止 Agent”“取消计算”是不同动作。只有服务支持且确认远端取消成功时，才能显示已取消计算。切换页面、消息淡出或关闭历史不影响任务。

## 7. 实现分工与顺序

1. **通用异步执行闭环。** 在现有 Runner、调度器、工具执行契约和上下文组装器上接入托管执行、至多 240 秒的让出窗口、运行态快照、自动等待、终态续接与独立计量。OGE 复用 AnalysisJob 和监督器，不新增业务或模型等待工具。首先验证“超过 4 分钟仍运行 → 模型说明 → 框架自动等待 → 完成后继续”，全程只提交一次。
2. **Agent 地图展示工具。** map_present 关联受限业务对象，接通候选/成果展示、工具发起的视图切换、定位及展示回执；明确实时请求与历史恢复的区别。
3. **地图会话视觉。** 复用现有消息数据及块投影，增加轻消息带、历史展开和常驻操作位，复用输入、问题与审批；不要直接挂第二份完整 MessageList。
4. **卫星影像候选与选择。** 复用现有影像检索，保存候选集、编号和选择，接覆盖范围及自然语言选择。对象标签是传递真实输入的组成部分，不要求用户单独学习一套引用工作流。
5. **真实选景 NDVI 与完整验收。** 核验公开影像 ID 到 OGE 参数的映射，替换无参数默认输入，完成检索、展示、选择、计算、等待、上图及后续操作。前述界面与循环可先用明确标记的录制数据验证。

当前 NDVI 仍是无参数默认服务，成果为 RGB 显示影像；录制回放不能证明所选影像已经计算，也不能作为数值 NDVI、像元采样或面积统计的依据。[NDVI 参数](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/tools/oge/ndvi.py:11)、[成果边界](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/integrations/analysis_raster.py:44)

## 8. 验收标准

- 检索成功不切页；Agent 显式地图展示工具可以打开地图并定位。刷新、重连和历史回放不重复执行导航。
- “第二景”、所选卡片、传给服务的输入和结果来源一致；地图与对话共享消息、草稿和选择。
- 等待窗口达到 240 秒而执行未完成时，后台继续，模型看到真实运行态并自然回复；运行器自动等待和续接，不要求模型调用等待工具，没有重复提交、重复审批或虚假成功。
- 用户补充输入能在安全边界进入模型；进度事件不导致秒级模型轮询；完成结果能及时续接且只处理一次。
- 服务成功后由 Agent 的展示工具上图；展示失败可区分、可恢复。停止 Agent 不误报取消远端任务，也不被后台完成擅自重启。
- 普通消息逐行渐隐，重要操作与状态保留，完整历史可读；用户输入、阅读和拖图时保持焦点与布局稳定。
- 验证浅色、深色、窄屏、减少动态效果及任务重启恢复。录制演示与真实接口验收分别记录；按项目要求不新增测试文件，数据库变更归并到 schema.sql。
