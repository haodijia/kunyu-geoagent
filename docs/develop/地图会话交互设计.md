# 地图会话交互设计

更新：2026-10-15。根据用户对目标流程的补充，本阶段优先完成同一会话在对话页与地图页之间的连续体验。本文为设计与实现约定，本轮未修改业务代码。

## 1. 用户路径

1. 新建 session，在对话页说“帮我查询卫星影像”。
2. Agent 检索影像，调用展示工具；候选数据准备好后，当前会话自动进入地图，显示影像覆盖范围和候选列表。
3. 用户留在地图页，点选影像，或直接回复“第二景，计算 NDVI”。
4. Agent 确认具体输入，按已有审批契约调用 NDVI。工具在远端计算期间保持未完成，地图展示常驻作业状态。
5. 服务返回且成果准备好后，结果直接加入地图，展示图层与成果摘要；Agent 继续解释。
6. 用户调整地图、选择空间对象、修改图层或继续提问，所有操作仍属于同一个 session。

主界面由地图承载空间任务，对话页保留完整历史。选区、引用和来源等能力用于支撑这条路径，不要求用户先完成一套独立的准备向导。

## 2. 地图页构图

采用全幅地图，保留当前会话标题与视图切换。底部居中使用已有 Composer，宽度与对话输入框保持一致；正上方是轻量消息流和必要的操作位。Mu 的中性色、细边框、浅紫主操作继续沿用，过程文字保持安静、紧凑。

| 区域 | 展示内容 | 收起时机 |
| --- | --- | --- |
| 地图主体 | 检索覆盖范围、所选影像、分析图层 | 随当前任务切换内容，不随消息消失 |
| 一个临时对象区 | 当前候选列表，完成后替换为所选对象或成果详情 | 用户完成选择或主动关闭，不让多个任务面板叠加 |
| 底部轻消息 | 最近三行用户/Agent 文字，最新行最清晰 | 向上逐行渐隐，空闲后依次收起 |
| 常驻操作位 | 选择、审批、问题、运行状态、错误及恢复操作 | 完成、解决或明确关闭后收起 |
| 输入框 | 文字、所选影像/对象标签、现有附件和发送能力 | 始终可用；切换地图不清空草稿、不强制聚焦 |

地图下方仅在文字附近加柔和背景渐变。普通消息不用大气泡或逐条卡片；候选和成果也复用同一个紧凑区域。完整工具参数、模型思考与执行详情放在展开对话及已有轨迹中。

## 3. 逐行淡出的消息流

以下数值是首版设计参数，后续按实际观感调整：

- 默认保留 **3 个视觉行**，按实际容器换行计算；当前正在生成的一行保持清晰，前两行约为 65%、30% 强度。
- 新的一行出现时，旧行约 **240–280ms** 向上移动；顶部通过渐变遮罩离开。流式 token 更新当前行，不为每个 token 重建动画。
- 文字生成结束后停留约 **10 秒**，再从最旧一行起依次淡出。行高稳定，输入框位置不跳动。
- 鼠标悬停、键盘聚焦或展开历史时暂停淡出。恢复跟随时直接展示最新几行，不补播积压动画。系统减少动态效果时直接更新。
- “展开对话”在原底部区域向上展开，最多约占地图高度 45%；阅读历史时停止自动跟随，新消息显示一个提示。收起后回到轻消息流。
- 淡出仅影响地图上的显示，**不会删除消息或日志**。对话页、地图展开历史和轨迹读取同一份会话事实。
- 屏幕阅读器只接收新增内容与关键状态，不重复播报每次透明度变化和计时刷新。

## 4. 检索、选景与展示工具

Agent 应有明确的空间展示能力，例如 `map_show_image_candidates`。它接收本轮已保存的检索结果引用，准备候选及覆盖范围，并发出当前会话的地图展示请求；不接受任意 URL 或前端脚本。

候选按本次检索固定编号，保留 imageId、产品、时间、云量、分辨率和可用空间范围。地图上的覆盖范围、候选卡与“第二景”的文字回复必须指向同一候选集；新的检索产生新的候选集。空间坐标缺失或坐标系未核实时保留卡片，明确覆盖范围不可用。

点击候选只选中并预览，不自动发送消息、不抢输入焦点。用户说“用第二景算 NDVI”，或点击明确的计算操作后，提交所选影像和本轮指令；后端解析真实对象并冻结输入。现有问题与审批机制在同一个常驻操作位显示，不叠加新的确认弹窗。

展示工具与路由分工：工具保存数据及发布展示意图；会话级前端桥接消费新的实时请求，切到地图并定位。请求包含稳定的 request_id、session_id、run_id，一次消费；历史重放仅恢复数据，不重新导航。用户已离开当前任务、阅读历史或手动调整地图时，保留“查看/定位结果”入口，不反复拉回页面。

## 5. 长任务等待

当前 NDVI 工具已采用“提交 → 等待监督器 → 获得已准备成果 → 工具完成”的生命周期，可直接沿用。[服务工具](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/tools/oge/service.py:79)

Agent 可以在调用前生成一次真实说明：“我会计算这景影像，请稍等，完成后会直接显示。”主模型在工具等待期间不继续下一次模型请求；期间由作业事件更新界面，不伪造新的助手消息，也不让模型反复查询状态。[运行循环](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/runtime/runner.py:210)

常驻状态行展示“已提交 / 运行中 / 正在准备地图”、已等待时间及可用操作。只显示服务真实报告的阶段；没有百分比时不虚构进度。失败、鉴权失效、查询失联或提交状态未知保持可见，复用对应错误和恢复动作。

等待期间地图仍可操作，输入框仍可接收补充要求。新要求进入现有输入队列，在下一个安全步骤处理；不能宣称已修改正在远端执行的输入。停止本地等待与取消远端计算分别表达，当前没有远端取消能力时不得显示“远端任务已取消”。

## 6. 结果直接显示与后续操作

对于本轮明确要求显示的计算，成果准备好后，由同一应用用例幂等创建地图图层及定位请求；不必等待模型再补上图、定位两次调用。前端复用现有成果和地图事件投影。返回工具结果时明确区分“成果已保存/图层已登记”与当前画布是否完成渲染。

若用户仍在原任务视角，可平滑定位成果；若已主动拖动地图，则新增图层并提供“定位结果”，保留当前相机。历史恢复或后台任务完成不抢页面。

成果在地图上保留，解释文字可以淡出。用户可调整透明度、显隐，或点选后继续提问；新的计算输入产生新成果，展示样式修改不重新计算。统计、采样与数值图例只在成果真实支持时出现。

## 7. 当前接缝与实现顺序

现有 MapView 已复用 SessionComposer、AgentControls 和会话 Provider，优先扩展这些入口。[MapView](/Users/dijkstra/project/01-python/kunyu-geoagent/frontend/src/features/sessions/views/MapView.tsx:69)

1. **地图轻消息与等待状态。** 从已有消息、内容块与实时流投影最近几行，复用输入和审批。新增轻量呈现容器，不直接挂第二份完整 MessageList，避免重复滚动锚点与工具卡。
2. **展示请求与自动进入地图。** 扩展会话事件，区分 opened 历史与实时 event，避免重连抢页。先用现有默认 NDVI 成果验证“展示 → 等待 → 自动上图”的视觉与时序。
3. **卫星影像候选。** 复用现有检索服务，持久化候选集、稳定编号及选择；接覆盖范围、对象标签和自然语言选景，确保后端与模型收到真实输入。
4. **所选影像接入 NDVI。** 核验公开影像 ID 到 OGE 参数的映射，替换当前默认输入契约，再完成真实选景计算。界面原型或默认录制回放不能冒充该功能已联通。

目前消息 Provider 会把 opened 历史与实时事件合入同一集合，不能简单监听全部 `tool.completed` 后导航。[事件入口](/Users/dijkstra/project/01-python/kunyu-geoagent/frontend/src/features/events/api.ts:20)、[会话事件 Provider](/Users/dijkstra/project/01-python/kunyu-geoagent/frontend/src/features/events/SessionEventContext.tsx:95)

当前 NDVI 仍是无参数默认服务，成果为 RGB 显示影像；本轮演示中的候选、选景计算和等待时长均是交互示意，实际录制预览只用于展示布局。[NDVI 参数](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/tools/oge/ndvi.py:11)、[成果边界](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/integrations/analysis_raster.py:44)

## 8. 首版手工验收

- 当前会话的实时展示请求进入地图一次；刷新、重连和打开历史不会触发重复切换。
- 地图与对话切换保留草稿、所选候选和运行状态；当前句可读，普通文字逐行淡出，完整历史可展开。
- 候选选择、待审批、待回答、运行状态与错误不会被普通消息的淡出隐藏。
- 长任务等待不产生额外模型轮询，停止等待不重发计算；成果准备好后直接可见。
- 用户阅读历史、输入和拖动地图时不被抢焦点或反复定位。
- 浅色、深色、窄屏与减少动态效果模式下保持可用。录制演示与真实接口验收分别记录，不新增测试文件。
