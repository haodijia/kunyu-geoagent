# 地图与 Agent 连续会话：最终设计方案

更新：2026-10-16。长工具以本地 deepseek-harness 的 `jobs / jobs-local / tool-jobs` 实际源码为基准。下文区分参考项目已有机制、本项目已移植部分及尚未接入的部分；本轮仅更新文档，未修改业务代码。

## 1. 产品约定

- **session 是唯一会话。** 对话页和地图页共享消息、草稿、选择、审批与任务；地图页是同一会话的空间操作界面。
- **Agent 用工具决定展示。** 检索成功只产生数据。Agent 需要让用户选景时，显式调用地图展示工具，打开当前会话的地图、定位并展示候选；前端不能根据“检索完成”自行切页。
- **长工具按 harness 的 jobs 处理。** 工具主动登记 job，前台等待到期返回 job ID 与已有输出，任务继续。模型通过通用 `job_output` 读取或限时等待；完成通知注入忙碌 Agent 的下一步，默认唤醒空闲 Agent。业务层不新增 `wait_task`。
- **地图展示保持轻量。** 全幅地图、底部逐行渐隐消息、同一个输入框、必要的候选/成果操作区与任务状态条。

## 2. 完整业务流程

| 步骤 | Agent / 工具 | 用户界面 |
| --- | --- | --- |
| 新建会话 | 接收“查询卫星影像”及已有区域、时间条件；缺少必要条件时询问 | 普通对话页，保留当前输入习惯 |
| 检索影像 | `oge_search_images` 返回一组持久候选及元数据 | 显示真实检索过程；检索本身不导航 |
| 邀请选景 | Agent 调用 `map_present`，目标为候选集，要求打开地图、定位并供用户选择 | 当前 session 切到地图，显示覆盖范围与候选；输入框和草稿保持 |
| 用户选择 | 点选仅预览；“使用此景”或“第二景，计算 NDVI”提交明确选择 | 所选影像高亮，输入区显示对象标签；已明确选择不再重复追问 |
| 发起计算 | 后端冻结影像、区域与参数；Agent 调用 `oge_calculate_ndvi`，复用已有审批 | 原位置承接审批与任务状态，无新增确认弹窗 |
| 返回后台任务 | 工具登记通用 job；前台等待到期返回同一 job ID、当前状态和已有输出，计算继续 | 显示真实阶段与耗时；模型根据工具回执自然回答 |
| 获取后续结果 | 模型通过 `job_output` 读取或限时等待；完成通知按 harness 的 inject / followup 送达，不重新提交 | 地图与输入仍可操作；普通文字淡出，任务状态保留 |
| 展示成果 | Agent 获取成功成果后调用 `map_present`，目标为成果并要求上图 | 添加图层、定位及成果操作；展示结果进入模型上下文，随后解释 |
| 继续交互 | 新指令携带所选影像、对象、图层或任务引用，调用对应工具 | 调透明度、查看来源、选择范围或继续分析，全程留在该 session |

## 3. 工具边界

下列为目标契约；`map_present` 及通用 jobs 需要实现，不是当前已存在的完整能力。后台任务登记、增量输出、限时等待与完成通知按本地 harness 移植，业务工具负责实际业务执行。

| 工具 | 职责 | 返回内容 |
| --- | --- | --- |
| `oge_search_images` | 按区域、时间等条件检索并保存候选集 | candidate_set_id、稳定编号、影像 ID 与已知元数据 |
| `map_present` | 显式打开当前会话地图、展示指定候选或成果，按指令定位；候选可进入选择交互 | 展示请求 ID、目标引用、当前可核实的展示状态 |
| `oge_calculate_ndvi` | 提交一次计算并登记为通用 job；前台完成则直接返回结果，等待到期则返回后台任务 | job ID、当前输出和状态，或实际结束结果 |
| `job_output` | 沿用 harness：读取同一 job，或通过 `wait: true` 有限等待 | 新增输出、首次读取的终态结果与当前状态；等待到期仍可为 running |
| `job_list` / `job_kill` | 沿用 harness：列出所属任务、请求取消 | 实际状态；请求取消不等于已经停止 |
| 现有地图查询/样式工具 | 读取地图上下文、修改图层显隐、透明度和顺序等 | 实际应用的地图版本与状态 |

`map_present` 通过受限的目标类型引用候选集或成果，不接收任意路由、URL 或前端脚本。页面切换、展示内容、空间定位均来自工具的明确指令；工具可将相关动作合成一次调用，减少不必要的往返。

候选展示与计算成果展示共用同一个工具入口，分别使用明确的参数类型；地图数据与渲染实现仍按职责分层。现有低层地图能力按实际用途整理，替换的旧入口完整删除。

## 4. 长工具按 deepseek-harness 源码对齐

### 4.1 采用的执行链路

这不是 AgentLoop 自动把所有 async 工具变成后台任务。harness 将后台能力拆成 `jobs` 服务契约、`jobs-local` 进程内实现、`tool-jobs` 模型工具与完成通知；基础产品组合同时安装后两者。生产工具主动注册 job，并保有实际执行资源。

以 Bash 工具为例：开始调用时 `registry.start()` 登记进程，显式后台立即返回 job ID；前台等待到期返回 `kind: promoted`、同一 job ID 和已有输出，进程继续。模型随后使用通用 `job_output`，不重新启动命令。[登记与等待](/Users/dijkstra/project/02-ts/deepseek-harness/packages/shell/tool-bash/src/index.ts:296)、[转后台返回](/Users/dijkstra/project/02-ts/deepseek-harness/packages/shell/tool-bash/src/index.ts:368)

```text
工具提交业务一次，并登记 owner 所属的 job
  → 前台等到完成，或等待到期返回同一 job ID + 当前输出
  → 模型自然解释状态，继续独立工作或调用 job_output
  → job_output(wait=true) 等到完成或本次等待到期
  → 到期仍运行：返回 running，job 继续
  → 未被等待调用交付的完成：发出会话 notice
      → owner 忙碌：inject 到下一步
      → owner 空闲：默认 followup 唤醒新一轮
  → 模型用 job_output 取得结果
  → Agent 调用地图工具展示成果
```

`job_output` 默认非阻塞；`wait: true` 默认等 30 秒，单次上限默认 10 分钟，均可配置。等待到期返回状态，不抛工具超时、不终止任务。用户提出的最多等待 4 分钟可通过已有等待参数表达，不需要另设计轮询协议。[参数与默认值](/Users/dijkstra/project/02-ts/deepseek-harness/packages/jobs/tool-jobs/src/index.ts:40)、[等待实现](/Users/dijkstra/project/02-ts/deepseek-harness/packages/jobs/tool-jobs/src/index.ts:310)

### 4.2 通知与上下文

- 模型通过发起工具返回、`job_output` / `job_list` 返回及完成 notice 获知状态。当前源码没有每轮自动扫描全部 running jobs 的上下文插件。
- `tool-jobs` 只订阅 settled 发送完成 notice；忙碌 owner 用 `inject`，空闲 owner 在默认 `completionDelivery: wakeup` 下用 `followup`。可配置 quiet 或连续唤醒上限；不是前端收到 SSE 后自行发起模型请求。[完成送达](/Users/dijkstra/project/02-ts/deepseek-harness/packages/jobs/tool-jobs/src/index.ts:271)
- 若完成已释放正在等待的调用、模型自己请求 kill、owner 销毁或任务无 owner，则按参考实现抑制重复通知。notice 提示完成，模型仍通过 `job_output` 收集结果。
- 系统提示要求记住 job ID、不忙轮询、不重复执行；有独立工作就继续，需要结果时才阻塞等待。无需规定模型在调用前或每隔固定时间说一次“正在计算”。[系统提示](/Users/dijkstra/project/02-ts/deepseek-harness/packages/jobs/tool-jobs/src/index.ts:249)
- 模型读取推进消费游标，终态结果只交付一次；界面通过独立 offset 观察输出，不抢模型的输出。每次工具调用/返回正常配对；本次工具调用可正常返回，但后台 job 仍为 running 时不能记为任务完成，等待到期不记远端失败。[模型与界面读取](/Users/dijkstra/project/02-ts/deepseek-harness/packages/jobs/jobs-local/src/index.ts:316)、[结果消费](/Users/dijkstra/project/02-ts/deepseek-harness/packages/jobs/jobs-local/src/index.ts:444)
- `job_kill` 先返回 cancellation-requested，实际停止后才结算 killed。停止当前 Agent 回合与销毁 owner scope 不同；不把停止等待误记为远端取消。

### 4.3 本项目接入边界

本项目已经移植插件/作用域、AgentLoop、工具批次、收件箱与持久轨迹，但没有移植 `jobs / jobs-local / tool-jobs` 通用链路；子 Agent 的后台委派是专用实现，不能据此宣称通用后台工具已经完成。[插件组合](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/bootstrap.py:93)

OGE 已有 AnalysisJob 和独立监督器，能保存远端身份并继续查询、恢复；缺口是它与 Agent 通用后台任务、模型工具和完成送达的连接。当前服务工具仍阻塞等成果，默认 15 分钟后抛 ANALYSIS_WAIT_TIMEOUT，而不是返回 running；Runner 等待整个工具批次。[服务工具](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/tools/oge/service.py:43)、[工具批次](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/runtime/runner_tools.py:322)、[已有监督器](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/application/analysis_supervisor.py:20)

下一步移植上述通用 jobs 能力，OGE 作为生产工具接入，复用 AnalysisJob 事实与现有监督，不新增 NDVI 专用等待协议。harness 的 `jobs-local` 本身是进程内实现，owner/service 销毁会清理任务；不能把它描述成跨应用重启恢复机制。OGE 的远端持久监督与本地 job 生命周期需要明确连接，不能直接声称两者取消、恢复语义相同。[参考实现的销毁清理](/Users/dijkstra/project/02-ts/deepseek-harness/packages/jobs/jobs-local/src/index.ts:614)

## 5. 地图页面与动态视觉

继续参考本地 Mu 的中性色、细边框、浅紫主操作和紧凑过程行，复用现有 shadcn/ui、SessionComposer、AgentControls 与消息内容投影。轨迹沿用 deepseek-harness 已采用的事实事件与多视图投影方式，不建设第二套地图聊天服务。

| 区域 | 设计 |
| --- | --- |
| 主画布 | 地图占主视觉，承载影像覆盖范围、所选对象、成果图层 |
| 临时对象区 | 候选列表与成果详情使用同一个紧凑区域；选择完成后收起候选，保留所选影像标签 |
| 底部消息带 | 与输入框对齐，默认显示最近 3 个视觉行；普通文字不用大气泡或独立卡片 |
| 任务/操作位 | 保留真实运行状态、待选择、待审批、待回答和错误；直到处理后收起 |
| 输入框 | 始终是同一份草稿与发送机制，支持直接回复“第二景”“运行 NDVI”和后续问题 |
| 历史 | 在底部区域向上展开完整对话，最多约占地图高度 45%；完整轨迹继续从已有入口查看 |

### 消息流动效

- 当前生成的行保持清晰，新行出现时，旧行以约 240–280ms 向上移动；较旧两行依次弱化到约 65%、30%，顶部通过渐变退出。
- 按真实容器换行计数，token 更新当前行，不为每个 token 重播动画；流式输出结束后停留约 10 秒，再逐行淡出。
- 悬停消息、键盘阅读和展开历史时暂停渐隐；阅读历史时停止自动跟随，新消息用轻提示承接。恢复时展示最新内容，不补播积压动画。
- 待选择、审批、问题、运行任务和错误不参与普通文字淡出。历史消息完整保存；减少动态效果模式下直接更新。
- 输入框不随消息行数跳动；文字附近使用柔和背景渐变保证可读性，地图其余区域保持清晰。无障碍播报只关注新内容和关键状态，不播报透明度及每秒计时。

## 6. 选择、展示与用户控制

**选景一致性。** 每次检索形成固定候选集和编号，点选、覆盖范围与“第二景”指向同一个对象。后端校验 session 归属与版本，提交时冻结影像、AOI 和参数。运行中修改地图或选择只影响后续操作，成果明确标明实际输入。

**导航由工具驱动。** 只消费当前会话中新发布的地图工具展示请求；按 request_id 处理一次。历史恢复、SSE 重连、后台任务完成都不能自行触发导航。若存在明确的新工具请求，可执行对应切换；当前已处于地图时就地展示。

**相机与焦点。** 工具可以要求定位。用户正在拖图或编辑时，先展示内容并承接定位请求，避免中途打断操作；保留“定位结果”入口。不强制聚焦输入框、不清空草稿、不持续追踪覆盖用户相机。

**成果与展示分别记录。** 计算成功只说明成果可用；Agent 再调用地图展示工具。前端记录展示请求与当前画布可核实的状态；加载失败时保留“计算完成、地图显示失败”及重试动作，Agent 据工具返回信息解释，不提前声称已经显示。

**停止语义明确。** “停止等待”“停止 Agent”“取消计算”是不同动作。只有服务支持且确认远端取消成功时，才能显示已取消计算。切换页面、消息淡出或关闭历史不影响任务。

## 7. 实现分工与顺序

1. **补齐 harness 通用 jobs。** 按 `jobs / jobs-local / tool-jobs` 移植登记、owner 生命周期、增量输出、`job_output / job_list / job_kill`、完成通知与默认唤醒；OGE 作为生产工具接入，复用 AnalysisJob 与监督器。验证长任务只提交一次、等待到期仍为 running、完成送达不重复。
2. **Agent 地图展示工具。** map_present 关联受限业务对象，接通候选/成果展示、工具发起的视图切换、定位及展示回执；明确实时请求与历史恢复的区别。
3. **地图会话视觉。** 复用现有消息数据及块投影，增加轻消息带、历史展开和常驻操作位，复用输入、问题与审批；不要直接挂第二份完整 MessageList。
4. **卫星影像候选与选择。** 复用现有影像检索，保存候选集、编号和选择，接覆盖范围及自然语言选择。对象标签是传递真实输入的组成部分，不要求用户单独学习一套引用工作流。
5. **真实选景 NDVI 与完整验收。** 核验公开影像 ID 到 OGE 参数的映射，替换无参数默认输入，完成检索、展示、选择、计算、等待、上图及后续操作。前述界面与循环可先用明确标记的录制数据验证。

当前 NDVI 仍是无参数默认服务，成果为 RGB 显示影像；录制回放不能证明所选影像已经计算，也不能作为数值 NDVI、像元采样或面积统计的依据。[NDVI 参数](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/agent/tools/oge/ndvi.py:11)、[成果边界](/Users/dijkstra/project/01-python/kunyu-geoagent/backend/src/kunyu/integrations/analysis_raster.py:44)

## 8. 验收标准

- 检索成功不切页；Agent 显式地图展示工具可以打开地图并定位。刷新、重连和历史回放不重复执行导航。
- “第二景”、所选卡片、传给服务的输入和结果来源一致；地图与对话共享消息、草稿和选择。
- 前台等待到期而任务未完成时返回 job ID 与当前状态，任务继续；`job_output` 等待到期返回 running，没有重复提交、重复审批或虚假成功。
- 完成时按 harness 向 busy owner inject、向 idle owner 默认 followup；已由等待调用交付的完成不重复通知，结果消费与界面观察不互相干扰。
- 服务成功后由 Agent 的展示工具上图；展示失败可区分、可恢复。停止、scope 销毁、请求取消与确认远端取消按真实能力处理；已销毁 owner 不再收到完成唤醒。
- 普通消息逐行渐隐，重要操作与状态保留，完整历史可读；用户输入、阅读和拖图时保持焦点与布局稳定。
- 验证浅色、深色、窄屏、减少动态效果及任务重启恢复。录制演示与真实接口验收分别记录；按项目要求不新增测试文件，数据库变更归并到 schema.sql。
