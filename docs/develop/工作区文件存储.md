# 工作区文件存储

工作区使用后端托管目录，不需要用户选择本机文件夹。创建工作区时立即建立目录；启动后端时补齐已有活跃工作区的目录。目录名使用稳定工作区 ID，中文名称存于数据库供界面展示，重命名不移动文件。工作区移除后，其文件保留，与已归档会话一样不做物理删除；移除的工作区不再接收新上传。

## 目录

```text
KUNYU_APP_DATA_DIR/
├── kunyu.db
├── attachments/                  # 对话附件
├── skills/                       # 用户技能
└── workspaces/
    └── <workspace_id>/
        ├── skills/               # 工作区技能（按需建立）
        └── files/                # 模型的 /workspace
            ├── images/           # 图片原始文件
            └── data/             # 其他原始文件
```

`images/` 和 `data/` 按上传需要建立。新目录权限为 0700，新文件为 0600。用户文件保留原名，不使用内容 hash 命名；重名采用 `照片-2.png`、`照片-3.png` 等编号，不覆盖已有文件。模型使用 `glob`、`grep` 发现工作区文件，使用 `read`、`read_image` 读取；同一工作区的不同对话共享这些路径。

桌面开发版通过 Electron 的 `app.getPath("userData")` 确定根目录：

| 系统 | 数据库路径 |
| --- | --- |
| Windows | `%APPDATA%\kunyu-electron\kunyu.db`，通常为 `C:\Users\<用户名>\AppData\Roaming\kunyu-electron\kunyu.db` |
| macOS | `~/Library/Application Support/kunyu-electron/kunyu.db` |
| Linux | `${XDG_CONFIG_HOME:-~/.config}/kunyu-electron/kunyu.db` |

Windows 可以在资源管理器地址栏输入 `%APPDATA%\kunyu-electron` 打开数据目录。路径依据 [Electron 标准应用数据目录规则](https://www.electronjs.org/docs/latest/api/app#appgetpathname)。

后端独立启动时可通过 `KUNYU_APP_DATA_DIR` 设置根目录，数据库为该目录下的 `kunyu.db`。桌面启动会将 Electron 数据目录写入后端的这个环境变量。该路径属于后端部署环境，不向模型注入工作区标识、宿主机路径或地图快照。

## 上传

工作区菜单的“上传工作区文件”打开上传弹窗。支持选择多个文件、拖入文件、查看结果、取消队列和复制返回的模型路径。弹窗由应用外壳持有，窗口变窄或侧栏收起不会卸载它；路由切换或关闭弹窗会停止尚未完成的上传。

工作区上传与对话附件是两套用途：前者保存可重复使用的项目文件，后者仍通过已有消息附件接口提供会话内的引用和请求图片。上传文件不会自动插入会话历史或提示词，用户通过返回路径引用即可。

接口：

```text
POST /api/v1/workspaces/<workspace_id>/files?name=<文件名>&kind=image|file
Content-Type: application/octet-stream
X-Kunyu-Session: <桌面会话令牌>
Body: 原始文件字节
```

返回 `201`：

```json
{"name":"照片.png","file_path":"/workspace/images/照片.png","bytes":1024,"kind":"image"}
```

每个上传最多 64 MiB，原始图片不进行缩放、转码或移除元数据。模型的 `read_image` 仍按既有图片格式、16 MiB 源文件限制和模型图片能力执行，并为模型请求生成所需图片内容；不会修改工作区原文件。

服务端先确认活跃工作区，再读取有界请求体，发布前在事务内重新确认工作区。目录和文件通过已有 descriptor-relative、no-follow IO 访问，私有暂存、fsync 和原子独占发布保证完整内容后再返回结果。非法文件名、过大内容、无效工作区和存储失败均明确报错；存储失败记录日志。用户手动上传不改变 Agent 的权限模式。

创建工作区时先在数据库事务中插入记录，再初始化目录，成功后提交；目录失败会回滚记录。文件目录与 SQLite 是独立资源，极端进程中断可能留下尚未对应已提交记录的空目录，不会向前端返回成功创建的工作区。

## Docker 数据目录方案

建议容器内使用 `/data/kunyu`，将 `KUNYU_APP_DATA_DIR` 设置为这个路径。宿主机可以将 `/srv/kunyu-data` bind mount 到该目录，或使用 named volume 挂载同一目标。代码、数据库和上传文件不混放；备份整个数据根目录即可涵盖工作区内容。

本次完成数据目录可配置与持久化布局，尚未提供完整 Docker 镜像、Web 启动和部署认证配置；现有 CLI 仍为桌面 sidecar。

## 核验

- 新工作区立即建目录，已有工作区在启动时补齐，目录失败回滚数据库记录。
- 中文文件名、原图字节、重复与并发重名、重命名后路径稳定、移除后拒绝上传。
- 服务器 64 MiB 上限、无部分文件发布、路径穿越和符号链接目录拒绝。
- 实际 Agent 在第二个会话调用 `read_image`，三种 SDK API 均接收图片，原文件不变；文本 `write/edit/read` 与日志重建通过。
- Electron 实际上传、错误提示、取消队列，以及浅色/深色/窄窗口核验通过。未调用付费模型或业务服务，没有新增仓库测试文件。
