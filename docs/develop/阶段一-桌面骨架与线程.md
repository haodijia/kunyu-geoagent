# 阶段一：桌面骨架与线程

> 状态：待开发
>
> 目标：从空目录开始，建立 Electron、React 和 FastAPI 三个边界清晰的工程，完成可持久化的项目—线程—消息主链和首个可交互桌面壳。

## 1. 开发方式

阶段一严格按本文的 commit 顺序开发。每个 commit 必须满足：

1. 只交付一个可独立说明和审核的结果；
2. 不预先夹带后续 commit 的页面、接口或抽象；
3. 不留旧实现、兼容分支、假数据或静默降级；
4. 通过当前 commit 列出的检查后再提交；
5. 提交完成后停止开发，等待人工审核和下一次指令。

若审核要求调整当前 commit，修改应继续收敛在当前功能内，不开始下一个 commit。

## 2. 阶段边界

### 2.1 本阶段交付

- Electron 单窗口桌面壳；
- Electron 自动启动、健康检查和关闭 FastAPI；
- React 启动页、任务侧边栏和 ThreadWorkspace；
- SQLite 中的 Project、Thread、Message 和事件；
- 项目、线程和消息 API；
- 携带桌面 session header 的 REST 和 SSE 客户端；
- `概览 | [对话 ↔ 轨迹] | 地图` 路由与状态保持；
- 退出重启后可重新打开已保存的线程和消息。

### 2.2 本阶段不做

- DSH Host、Runner、Tool 和 Memory；
- 真实模型调用和 Assistant 回复；
- OGE 连接、任务和成果；
- 真实地图成果图层与遥感数据；
- GeoSkill、设置页、报告、核查和 Artifact 详情；
- 打包签名、自动更新和发布流程。

本阶段“发送消息”只保存真实的 User Message 并发布事件，不伪造 Assistant 回复。第二阶段接入 DSH 后再生成模型消息。

## 3. 工程基线

| 子工程 | 基线 |
| --- | --- |
| `electron/` | Electron + TypeScript，独立 `package.json` 和锁文件 |
| `frontend/` | React + TypeScript + Vite，独立 `package.json` 和锁文件 |
| `backend/` | Python + FastAPI + Pydantic + Uvicorn，使用 `uv` 管理 `pyproject.toml` 和 `uv.lock` |
| 服务端状态 | TanStack Query |
| 本地界面状态 | Zustand |
| 前端路由 | Hash Router |
| 数据库 | SQLite WAL + SQLAlchemy 2 + Alembic |
| 地图壳 | OpenLayers，本阶段不连接外部底图 |

Electron Renderer 始终关闭 Node 集成并开启 `contextIsolation`。桌面 session token 只存在 Electron、preload 和 Renderer 内存中，不写入 URL、SQLite 或 Web Storage。

**结果**

**范围**

**检查**

### P1-05 `feat(electron): manage fastapi sidecar startup`

**结果**

Electron 生成 session token，启动 FastAPI，解析 ready JSON 并完成健康检查。

**范围**

- 创建 backend process manager；
- 开发环境固定执行 `uv run --project backend python -m kunyu.main --desktop`；
- 实现启动超时、ready 协议校验和健康检查；

### P1-06 `feat(electron): expose secure runtime bridge`

**结果**

Electron 在后端就绪后加载 React，preload 只向 Renderer 暴露受控的运行时连接信息。

**范围**

- preload 暴露只读 `baseUrl`、`apiVersion` 和内存中的 session token；
- 定义 Renderer 侧 TypeScript 类型；
- 开发环境加载 Vite URL，构建环境加载本地静态文件；
- 外部 URL 不在应用窗口内导航。

**检查**

- React 页面只在 backend healthy 后出现；
- Renderer 不存在 `require`、`process` 或任意 Node API；
- session token 不出现在 URL 和 Web Storage。

### P1-07 `feat(electron): stop sidecar with the desktop lifecycle`

**结果**

正常退出 Electron 时，FastAPI 先停止接收请求并优雅退出；超时后只结束由当前 Electron 创建的子进程。

**范围**

- 实现内部 shutdown endpoint；
- Electron 关闭流程阻止重入；
- 等待有限时间后回收子进程；
- 不按端口或进程名清理非本应用进程。

**检查**

- 正常关闭后 backend PID 不再存在；
- backend 已退出时，Electron 关闭不抛出未处理异常。

**检查**

## 5. 阶段验收

P1-21 审核通过后，按以下顺序进行一次完整手工验收：

1. 在全新应用数据目录启动 Electron；
2. 确认无需手工启动 FastAPI；
3. 新建项目和线程；
4. 收起、展开侧边栏，并在两个线程间切换；
5. 向线程发送一条消息；
6. 确认对话活动行和轨迹页展示同一真实事件；
7. 在对话输入未发送草稿，切换概览、轨迹和地图后确认草稿不丢失；
8. 移动地图视口，切换页面后确认视口保持；
9. 关闭 Electron，确认 FastAPI 子进程退出；
10. 重启 Electron，确认恢复最后线程、模式和已保存消息。

阶段一完成后，数据链路应为：

```text
Electron lifecycle
  → FastAPI ready / health / shutdown
  → Project / Thread / Message application services
  → SQLite + append-only events
  → REST / SSE
  → React sidebar / conversation / trace / map shell
```

只有上述链路在应用重启后仍成立，才进入阶段二的最小 DSH 开发。
