# Agent、OGE 服务与地图协同设计

日期：2026-10-13。本文是后续开发方案，未列为已实现的能力不得作为当前产品功能展示。

## 1. 开发目标与首个完整案例

以截图中的 NDVI 服务完成第一条真实分析链路：用户发起默认 NDVI → 后端提交服务 → 持久跟踪任务或收集同步结果 → 查看预览、下载原始成果 → 将具有地理定位信息的结果加载到 MapLibre → Agent 基于同一成果继续解释。

随后扩展用户选定影像和研究区、灾害监测服务、灾前灾后对比与统计。首期不开发通用算子编排编辑器、服务市场或复杂三维模型平台。

产品应共享四种明确对象：研究区、输入影像、分析任务、分析成果。地图图层引用这些对象，对话卡片、工具结果和轨迹也引用同一组 ID，不各自复制一套状态。

## 2. 当前基础与接口证据

当前已有 MapLibre 二维／三维地形地图、会话及运行轨迹、工具审批、OGE 登录设置，以及行政区、公开影像和我的数据查询工具。地图仍缺少业务图层、持久图层配置和分析任务面板。

截图可确认：

| 项目 | 内容 |
| --- | --- |
| 服务 | NDVI |
| 提交地址 | `https://api.openge.org.cn/gateway/management/gp-service/process/NDVI/api` |
| 方法 | POST |
| 鉴权 | Authorization，登录接口取得的凭据 |
| 输入 | `coverageID`、`productID`，均为 String |
| 默认值 | `productID=LC08_C02_L1`；coverageID 在截图中被截断 |
| 逻辑输出类型 | Coverage |

按用户说明，参数可全部省略。默认执行应省略这两个字段，不发送空字符串、不补造被截断的 coverageID。

单次实测已确认：JSON 空对象请求、Bearer 鉴权、异步返回 data.processId、GP 状态 0→1、结果元数据、TIFF/COG 获取与独立下载的 404。仍未确认完整默认输入、自选影像映射、失败状态码及独立原始下载的正确契约。

初次按截图子域名核查时发现证书主机名不匹配，未发出计算请求。随后核对官网前端的 /api 路由，使用证书匹配的 https://openge.org.cn/api/management/gp-service/process/NDVI/api 完成唯一一次真实提交。全程保持 TLS 校验，详见第 13 节。

现有《OGE OpenAPI 开发者手册》列出了以下路径；已验证官网 /api 对应的状态、元数据和 COG 路由，独立 download 路由实测为 404：

- `/gateway/computation-api/process/{processId}`：状态。
- `/gateway/computation-api/process/result/{processId}`：结果元数据。
- `/gateway/computation-api/styles/cog/{processId}`：图片预览。
- `/gateway/computation-api/process/result/download/{processId}`：原始文件下载。

此次官网 HTTPS /api 入口复用了现有登录令牌，任务 ID 可用于同一 computation-api 的查询。Coverage 是平台逻辑类型；本例实际取得三波段 uint8 COG，没有取得独立 NDVI 数值波段或 XYZ 瓦片。

## 3. 两种输入模式

### 3.1 服务默认示例

用户说“运行一次默认 NDVI”。工具明确选择 `input_mode=service_defaults`，不携带自选影像参数。界面标注“服务默认示例”，避免把结果归属于当前地图区域或当前选中影像。

任务保存实际提交参数为空、默认模式、服务定义版本和提交时间。只有取得平台返回的有效参数或可核验输入元数据后，才补充实际 coverageID、productID 和输入范围；无法取得时标记为未解析，不虚构来源。

### 3.2 用户指定影像

工具选择 `input_mode=selected_image`，提交完整 coverageID 和产品代码。两种模式互斥，不能因输入校验失败改用服务默认值。

需要建立并验证输入映射：

| 应用已有字段 | NDVI 参数 | 处理原则 |
| --- | --- | --- |
| 数字 imageId | coverageID | 不是同一标识，不能直接替换 |
| imageIdentification | coverageID | 可能相关，需要具体服务联调确认 |
| 数字 productId | productID | 不是同一类型；不能将数字转成字符串充当产品代码 |
| 产品代码，如 LC08_C02_L1 | productID | 经过服务兼容性校验后使用 |
| Personal:Asset 引用 | 服务影像输入 | 只有该服务明确支持时才开放 |
| Personal:Process 引用 | 后续服务输入 | 只有执行接口明确支持时才开放 |

首个 NDVI 服务只开放经过验证的输入类型，不将平台通用引用协议自动套用到这个已发布服务。

研究区首先用于检索、定位和统计选择。截图的 NDVI 没有 AOI 参数，因此画框不会改变计算范围；若要裁剪计算，需接入已验证的裁剪服务并将裁剪结果作为输入。

## 4. 页面与交互

继续使用现有会话视图切换器。地图占主内容区，保留底部输入框与 AgentControls，不另做一套聊天系统。

地图提供三个可开关的轻量面板：

- 图层：影像覆盖范围、分析结果、研究区，支持显隐、顺序、透明度、图例、定位与移除。
- 分析任务：服务名称、输入模式、状态、已运行时间和最新查询时间；没有平台进度时不编造百分比。
- 对象详情：选中影像、成果、图斑或研究区的元数据与“加入对话”操作。

任务与成果面板按用户操作打开，不因每次工具执行反复遮挡地图。地图控件、图例及来源署名避开输入框，沿用 mu 的中性色、细边框和浅紫色操作按钮。

对话中增加紧凑的分析任务卡片，复用现有工具展示与轨迹链路：

- 提交后显示本地任务 ID、服务、输入模式和状态。
- 成功后显示成果标题、预览、查看地图、下载预览、下载原始结果、基于该结果继续分析。
- 失败显示可操作的错误原因；计算失败和结果下载失败分开。
- 点击“查看地图”定位已有图层；重复点击复用图层，不再次运行服务。

同一任务在对话、地图和轨迹中保持同一个 ID。成果卡片可在地图资源尚不可用时展示预览与下载；不能把“可预览”误显示成“已上图”。

## 5. Agent 工具

OGE 工具继续平铺在 `agent/tools/oge/`。首个服务使用专门的参数模型；后续至少两个服务验证成功后，再提取必要的共同执行接缝。

| 工具 | 作用 | 首期边界 |
| --- | --- | --- |
| `oge_calculate_ndvi` | 提交默认或指定影像的 NDVI | 返回本地任务 ID，是否含远端 ID 由实际响应决定 |
| `oge_get_job` | 读取任务状态与成果摘要 | 常规读取本地持久状态；按需请求监督器刷新 |
| `oge_wait_job` | 有界等待任务变化或结束 | 等待后端事件，不循环调用模型；到时返回 pending |
| `oge_get_result` | 读取成果的元数据、范围与可用操作 | 参数使用本地成果 ID，不接受任意远端 URL |
| `oge_download_preview` | 取得任务成果预览 | 与现有卫星影像缩略图工具区分 |
| `oge_download_result` | 获取原始文件到托管成果目录 | 返回成果引用和状态，不把二进制放进模型上下文 |
| `map_get_context` | 读取当前会话地图选择 | 只读取本会话、当前有效对象 |
| `map_add_layer` | 将已有成果引用加入地图 | 不调用分析服务，不接受任意 JS |
| `map_fit_bounds` | 定位指定图层或对象 | 使用已验证范围 |
| `map_set_layer_style` | 修改显隐、透明度和色带 | 只改变显示，不改变栅格数值或分析结论 |
| `oge_sample_result` | 根据经纬度查询原始栅格像元值 | 栅格阶段加入；返回波段、原值、有效性与坐标 |
| `oge_result_statistics` | 对整景或已登记研究区计算统计 | 定量分析阶段加入；返回统计范围、有效样本与指标来源 |

服务提交复用已有 L2 审批与绑定机制，将服务定义版本、账号身份和实际参数纳入审阅。工具重放不能再次提交已开始的远端计算。地图业务配置写入使用现有 L1 权限；只读上下文和状态查询使用 L0。托管预览缓存沿用已有只读图片工具的存储方式；导出到用户工作区是单独的明确写入动作。

未登录、过期或服务不兼容时返回明确错误。令牌不出现在工具参数、模型历史、工具结果、图层 URL 或普通日志里。

## 6. 地图上下文如何进入对话

用户在地图选择对象后，通过“加入对话”把上下文变成可见的输入标签：研究区、输入影像、分析成果、选中图斑。用户能删除标签，并查看对象详情。

提交消息时保存对象引用与该对象的版本快照。模型只获得本次明确提交的上下文以及自行调用 map_get_context 的结果；不默认将所有可见图层和视口变化不断注入 System。

消息中的对象引用与本轮工具参数绑定：后续地图操作不会修改已经接受的输入快照。对象已被删除或版本失效时明确提示重新选择，不改用其他影像。

地图点击“分析这幅影像”应填入已选影像引用与输入模式；点击“分析这个区域”应先形成 AOI 上下文，再由 Agent 检索兼容影像。

## 7. 分析任务与远端监督

Agent Run 是模型执行过程，AnalysisJob 是一次远端计算。两者生命周期独立：结束对话或停止 Agent 不代表已经取消平台作业。

提交过程：

1. 冻结服务定义、输入模式、实际参数、账号身份及发起工具调用。
2. 先创建本地任务并记录提交意图，再发送请求。
3. 根据已验证响应契约保存远端 ID，或直接保存同步成果。
4. 异步任务由后端监督器查询；成功后收集成果，发布会话事件。
5. Agent 通过有界等待或后续对话解释成果，不在模型步骤中连续轮询。

任务状态：created、submitting、queued、running、collecting、succeeded、failed、submission_unknown。平台未提供 queued 或百分比时不人工推测。

查询状态与计算状态分离：鉴权过期、网络中断、重启恢复中都不等于平台计算失败。结果已计算完成、预览失败、原图下载失败分别保存。

提交超时且无法确认是否已受理时进入 submission_unknown，不自动重发。只有平台支持可靠幂等键或可查询提交记录时，才自动消除这种不确定性；否则保留待核查状态。

监督器有持久 next_poll_at、有界并发和有限退避，遵循平台频率限制。监督器读取状态不创建新的模型请求。应用重启恢复已登记的远端 ID，继续查询和收集，不重新提交。

账号失效时暂停需要鉴权的查询，提示用原账号重新登录；切换账号不能将旧任务移交给新账号。未提供远端取消接口时，产品只提供“停止等待”，不得把它标为“取消计算”。

会话归档不自动取消远端作业。存在仍需监督或状态不明任务时，永久删除会话应先解决任务归属，避免丢失远端作业记录。

## 8. 成果、预览与地图数据

每份成果保存：任务与会话 ID、输出名称、逻辑类型、实际格式、原始输出引用、来源账号引用、CRS、WGS84 范围、栅格尺寸、波段、NoData、数据类型、数值范围、预览状态、原图状态和地图状态。

预览文件与原始成果是不同对象：

- PNG/JPEG 预览用于图片查看、对话解释和预览下载。
- 原始 GeoTIFF/COG 保留原始数值，用于地图渲染和后续计算。
- 没有 CRS、空间范围或变换信息的图片只展示为预览，不推测地理位置。
- 原始投影四角不能直接当作 WGS84 范围；根据明确的 CRS 转换，或使用已验证的 bandStats 地理字段。

地图来源分两种明确类型：已验证的远端瓦片服务，或托管栅格渲染服务。若平台只返回 GeoTIFF，后端下载、校验元数据并准备可按范围读取的栅格，再提供 MapLibre 可加载的瓦片。实现前确认 Rasterio/GDAL 与当前 Python、Electron 打包环境的兼容性。

NDVI 是连续数值结果，需要固定数值到颜色的映射与数值图例；以实际数据范围、NoData、scale/offset 和服务定义配置为准，不能仅用图片颜色推导数值。二维、三维显示引用同一成果，三维只增加地形贴合，不改变 NDVI 值。

所有 OGE 请求由后端发起。浏览器只请求本地会话鉴权保护的元数据、图片和瓦片；MapLibre 仅对本地 API 请求添加桌面会话头，外部底图请求不携带它。

地图点击栅格时由后端查询原始像元值，标明波段、坐标和 NoData 状态；图斑点击返回对象 ID、属性及所属成果。Agent 的定量说明使用这些数值或统计结果，不从预览颜色估算。整景统计与研究区统计区分范围，排除无效像元并记录有效样本数；阈值定义与统计方法作为成果参数保存。

一个结果上图后保留图层来源与生成参数。图层样式改变不创建新的计算成果；真正改变阈值、输入或算法参数时，新建分析任务和成果。

## 9. 持久数据模型

第一期增加四张表，研究区阶段再增加第五张；统一纳入现有 schema.sql，不保留多套迁移基线。

| 表 | 主要内容 |
| --- | --- |
| analysis_jobs | session_id、run_id、tool_call_id、服务定义版本、账号引用、提交模式、请求参数、实际参数解析状态、远端 ID、计算状态、查询状态、next_poll_at、错误摘要 |
| analysis_outputs | job_id、输出名、平台逻辑类型、实际格式、输出引用、空间与栅格元数据、预览/原图/地图资源状态、本地文件引用 |
| map_layers | session_id、来源引用、名称、类型、样式、显隐、顺序、空间范围、版本 |
| map_states | session_id、中心、缩放、方位、俯仰、二维/三维模式、当前选中对象、版本 |
| analysis_rois | session_id、名称、EPSG:4326 GeoJSON、创建方式、版本 |

采用业务 ID 与整数版本，不给文件名添加 hash。文件存放在托管目录下，例如 results/<output_id>/ndvi.tif、preview.png，不让 Agent 指定任意下载路径。

数据库是图层与任务的事实来源。前端 Zustand 承载交互中的视图，TanStack Query 管理持久对象，持久变更通过 API 与会话事件同步。地图拖动保存适度防抖；Agent 与用户同时修改地图配置时通过版本校验处理冲突。

不另造一个工作流引擎。首期一个已发布服务对应一个 AnalysisJob，多输出对应多份 AnalysisOutput。后续确有裁剪→监测等多服务案例时再增加步骤关系。

## 10. 本地 API 与代码职责

以下均为拟新增接口，不是已提供的 OGE 端点：

| 本地接口 | 作用 |
| --- | --- |
| GET /api/v1/oge/services | 返回已注册且经过验证的服务说明，不暴露凭据 |
| GET /api/v1/sessions/{session_id}/analysis-jobs | 当前会话的分析任务 |
| GET /api/v1/analysis-jobs/{job_id} | 任务、输入模式、状态和成果摘要 |
| GET /api/v1/analysis-outputs/{output_id} | 成果元数据与可用操作 |
| GET /api/v1/analysis-outputs/{output_id}/preview | 已准备的预览图片 |
| GET /api/v1/analysis-outputs/{output_id}/download | 原始成果下载 |
| GET /api/v1/analysis-outputs/{output_id}/tiles/{z}/{x}/{y}.png | 已准备的栅格瓦片 |
| GET/PUT /api/v1/sessions/{session_id}/map | 地图配置与视口，写入带版本 |
| GET/POST /api/v1/sessions/{session_id}/rois | 研究区管理，后续阶段实现 |

正式提交入口复用 Agent 工具执行、现有审批和持久事件；若 UI 增加“运行服务”按钮，也进入同一提交用例和审阅契约，不绕开它直接向 OGE 请求。

建议按职责新增模块：

- agent/tools/oge/ndvi.py、jobs.py、results.py：模型参数、工具返回与调用归属。
- agent/tools/maps/：地图上下文、图层与视角工具。
- integrations/oge/execution.py：该已发布服务的准确 HTTP 契约。
- application/oge_jobs.py：提交用例、结果收集与持久监督器；必要时再拆收集模块。
- domain/analysis.py、persistence/analysis.py：任务、成果及数据访问。
- api/analysis.py、api/maps.py：会话鉴权、对象归属和响应。
- frontend/features/maps/：业务图层、图例、对象选择与轻量面板。
- frontend/features/analysis/：任务/成果卡片，供对话与地图复用。

服务地址、参数说明、显示文案、色带定义与结构分离，便于替换服务和国际化。接口只处理本地授权对象 ID；后端使用注册服务地址，不接受模型指定任意带凭据的 URL。

## 11. 分阶段实现与验收

### A. 接口联调与 NDVI 契约

确定证书匹配的正式入口和鉴权；核对请求体编码，执行默认参数请求，保留脱敏响应；确认同步/异步、实际输出、查询与下载路径。记录 coverageID/productID 完整默认值能否还原，以及自选影像是否兼容。

验收：有效登录下有一次真实成功调用，取得可验证结果；已发布服务的定义和输出契约可以准确编码。

### B. 提交、任务、预览与下载

实现专用 NDVI 工具、AnalysisJob/Output、监督器、原始结果和预览收集、任务卡片与错误状态。复用既有审批和图片展示。

验收：Agent 发起默认 NDVI，任务可追踪，预览可打开，原始成果可下载；离开页面不重复执行，重启不重新提交。同步服务也登记同一种成果模型。

### C. 成果上图与地图持久化

接入明确地理定位的成果、图层面板、色带图例、定位、图层样式工具和地图状态恢复。

验收：同一 NDVI 成果在二维/三维显示，图例与数值范围一致；窗口重启恢复图层和视角；没有定位信息时只显示预览，并明确地图资源缺失原因。

### D. 自选影像与研究区

完成已验证的输入映射，添加绘制与选择研究区、影像覆盖范围、加入对话标签和消息快照。
