# 统一栅格与动态视图

2026-10-25。数据库基线 15。

一个成果是一份有空间参考的原始数值 TIFF，`kind` 统一为 `raster`。波段数量不决定成果类型，也不决定视图数量。每个成果保存完整波段说明和若干视图，RGB 是引用三个波段的视图，连续色带和分类图是引用一个波段的视图。多视图不再拆分 TIFF 或创建子成果记录。

## Agent 输入

`oge_execute_code` 要求 `title`、`code`、`crs`、`scale` 和 `presentation`。原 `products` 参数已移除。Agent 必须在编写算法时同时声明每个输出波段的意义和推荐视图。已发布服务仍通过 `oge_get_service_definition` / `oge_execute_service` 调用；登记契约提供同一种 `presentation`。

```json
{
  "bands": [
    {"index": 1, "name": "ndwi", "title": "水体指数", "description": "由已核查绿光和近红外波段计算的归一化差值。", "unit": "1"}
  ],
  "views": [
    {"id": "water_index", "title": "水体指数", "description": "数值为光谱指数，不能直接作为已核实灾情。", "group": "指数", "bands": [1], "style": {"type": "continuous", "color_ramp": "blue", "stretch": {"method": "range", "ranges": [[-1, 1]]}}}
  ],
  "default_view": "water_index"
}
```

- `bands` 按 1 起始索引完整描述所有波段，名称唯一；`title`、`description` 必填，`unit` 可为 null。
- `views` 的 ID 唯一，选择已声明的波段，`default_view` 必须存在；不要求每个波段都有视图，也允许同一波段有多个视图。
- `continuous` 选择一个波段，色带为 `viridis` / `blue` / `gray`，使用显式值域或百分位拉伸。
- `rgb` 依红、绿、蓝顺序选择三个波段，支持任意实数类型，包括 float32；使用三个显式值域或共同百分位规则。
- 百分位格式为 `{"method":"percentile","percentiles":[2,98]}`，在至多 512×512 的预览样本中求每通道的范围，固定保存后用于预览和地图，避免不同瓦片拉伸不一致。常量通道的显示范围按明确规则扩展；没有有限预览样本时报告 `EMPTY_VIEW`。
- `classified` 选择一个波段，声明完整 `classes:[{value,label,color}]` 和 `transparent_values`。类别编码目前为整数，透明值属于已声明类别。
- 去除了旧的 32 产品限制。波段数仍受 TIFF、内存、工具请求大小及 OGE 本身的资源条件约束。

## 后续调整视图

新增 Agent 工具 `result_set_views`，输入为 `output_id`、`expected_revision`、完整 `views` 和 `default_view`，输出为更新后的成果及 summary。HTTP 对应 `PUT /workspaces/{workspace_id}/results/{output_id}/views`（统一 `/api/v1` 前缀）。它复用计算时的视图 Schema，只在本地读取原始 TIFF、验证分类并生成新预览，不修改源像元，也不调用 OGE。

保存要求原成果 revision 一致；要移除的视图若仍被任一地图图层引用，返回 409，需先显式移除图层。新缓存先暂存，校验成功后与数据库修订一起发布；捕获到事务失败时恢复暂存。已有图层同步更新标题、revision 和渲染缓存；未保存成功不会清理旧预览。

## 收集和输出

远端计算结束后下载一个 `result.tif`。收集器核对实际坐标系、实数数据类型、全部波段数量、实际已命名波段与声明的对应关系，以及分类视图的全部有效类别。TIFF 没有波段描述时，`source_name` 保持 null，语义来自本次显式声明，不根据颜色推断。名称、计数、索引或类别不一致时拒绝发布。

原始 TIFF 不修改、不拆分。按块读取每个波段计算有效像元数、极值、均值和分类频数；预览 PNG 按视图保存在 `.cache/results/<目录>/views/<view_id>.png`。分组、标题和图例均为数据，不含洪涝专用前端分支。统计事实由读取 TIFF 得出，算法的业务含义仍需根据代码和数据来源审查。

任务成功结果为 `{analysis_output_id, limitations, output}`，其中 `output.metadata` 包含：

| 字段 | 含义 |
| --- | --- |
| width / height / band_count / crs / bounds | 实际文件结构与空间信息 |
| bands | 声明信息、实际 dtype / nodata / source_name、每波段 summary |
| views | 视图定义及收集时解析的 render_ranges |
| default_view | 推荐视图 ID |

统一任务回执不变。较大结果通过 `result_file_path` 读取，不将 TIFF 二进制塞入模型上下文。每个成果有一个下载入口，返回原始完整 TIFF；已删除重复的 `/bundle` 下载接口。

## 地图和数值分析

`map_present` 的计算成果输入改为 `rasters:[{output_id,view_id}]`，与 `image_ids` 二选一。旧 `output_ids` 参数已移除。完整批次校验后才提交。图层唯一性为 `(session_id, output_id, view_id)`；同一 TIFF 的不同视图可同时存在和卷帘比较。

预览与瓦片接口接受 `view_id`；省略则使用成果的 `default_view`。图层预览使用图层保存的视图。所有渲染都只读取视图选择的源波段，按视图与样式区分缓存。

`map_sample_raster` / `map_region_statistics` 接受 `output_id`、可选 `view_id` 和可选 `bands`。省略 bands 时读取视图选择的波段；显式 bands 为唯一的 1 起始索引。RGB 通道与其他波段共用数值读取逻辑。

区域统计统一返回 `{output_id,view_id,bands:[...]}`；每项含 `band`、`title`、`unit` 和统计值。匹配分类视图时按图例返回分类面积，分类编码的极值／均值不作为区域业务统计返回；其他波段返回数值统计。区域按像元中心纳入、最多四百万像元，每个选中波段单独测量。前端直接拖动圈选并展示各波段统计，无需前置对话框。

## 既有数据迁移

显式脚本：`uv run --project backend python scripts/migrations/raster_views.py /path/to/kunyu.db`。执行前关闭桌面应用，先结束运行中的 OGE 作业。运行时只接受当前基线，不保留旧模型分支。

迁移先备份 SQLite，再生成新视图预览；事务中合并子成果、改写地图引用、保留图层 ID／顺序和可见性，并升级到 15。原始 TIFF 不改写；旧拆分文件和预览移入同一备份目录，任务结果 JSON 同步更新。历史对话和工具轨迹作为历史记录保留，不重写当时的调用参数。失败时参照备份恢复，不使用运行时猜测兼容。

本机迁移：30 条旧记录 → 10 个栅格、30 个视图，10 个地图图层保留。备份位于应用数据目录 `backups/20261025-083141-raster-views`。

真实远端验证：`job-c3198538-29b5-422e-812a-863b9e2bcc10`，自定义代码导出一个 10 波段 float32 TIFF，以同一通用收集器登记 11 个视图（RGB、连续色带和分类），无服务专用展示代码。验证使用独立临时工作区和 100 米导出，仅检验协议，不作灾情结论。代码调试时一次编译因使用已下线算子失败；修正为已核查的 `Coverage.binarization` 后提交一次实际计算。

本地视图修订已验证新增 RGB 组合、默认视图更新、过期版本拒绝、移除在用视图拒绝以及注入事务失败后的数据库／预览恢复。实机完成 21 波段洪涝视图切换与点查，数值和图例按所选 view_id 更新；RGB 直接点查得到三个通道，拖动矩形自动返回 26.899 km² 选区内各通道 268,904 个像元的统计。成果目录实机确认只有一个 result.tif。


## 工具接口审查

完整输入 JSON Schema 见同目录 `栅格工具输入.json`，由当前 Pydantic 参数模型生成。

| 工具 | 此轮变化 | 输入重点 | 输出 |
| --- | --- | --- | --- |
| oge_get_service_definition | 更新契约内容 | service_name 可省略 | 目录或 parameters / presentation / limitations |
| oge_execute_service | 更新统一成果收集 | title / service_name / parameters | 任务回执；完成后结果文件包含 analysis_output_id / limitations / output |
| oge_execute_code | 替换旧 products | title / code / crs / scale / presentation | 与已发布服务相同 |
| result_get_info | 返回统一栅格元数据 | file_path | 当前成果、revision、metadata、已筛选来源信息、summary |
| result_set_views | 新增 | output_id / expected_revision / views / default_view | 更新后完整成果和 summary |
| map_present | 更新栅格引用格式 | rasters:[{output_id,view_id}] 或 image_ids；open_map / focus | 含 view_id 的 layers |
| map_sample_raster | 支持选择任意波段 | output_id / longitude / latitude；view_id / bands 可省略 | inside / values / bands / units / band_indices / categories / output_id / view_id / summary，覆盖内还包含 row / column / crs |
| map_region_statistics | 统一多波段响应 | output_id / geometry；view_id / bands / values 可省略 | output_id / view_id / bands:[各波段统计] / summary |

所有 Agent 工具的 workspace、session 和凭证来自服务端绑定上下文，不在这些输入里传入。view_id 省略时使用明确声明的 default_view；bands 省略时使用该视图的通道。未声明业务含义的数值不会被平台自动归为水体、温度或其他类别。
