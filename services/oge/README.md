# OGE 双期水体变化服务

本目录是**发布到 OGE 的代码**。算法在 OGE 计算；坤舆只调用已发布接口、收集数值成果、生成图层并执行后续点查与区域统计。

## 已发布与已验证

2026-10-24 已通过在线开发中心发布 `flood_monitoring_bundle`，版本契约为 2.0.0。OGE 的“编辑服务”只允许修改名称和描述，故新版以独立名称发布；既有 `flood_monitoring` 保持原状态，未删除。

- 源码：`flood_monitoring.py`，直接粘贴到 OGE 开发中心，保存脚本后在资源行“…”选择“发布为服务”。不要在本机安装 OGE 来执行这个算法。
- 平台契约：`backend/src/kunyu/integrations/oge/services/flood_monitoring_bundle.json`。包含默认参数、21个波段的名称、分类含义、图例、分组及解释限制。新增服务只需登记对应契约，不添加案例专用地图按钮。
- 调用：`POST https://openge.org.cn/api/management/gp-service/process/flood_monitoring_bundle/api`，使用 OGE 登录得到的 Bearer Authorization。请求体 `{}` 使用全部已发布默认值；如 `{"ndwiThreshold":0.02,"mndwiThreshold":0.01,"thresholdStep":0.05}` 调整方法参数。
- 返回 `processId=job-...` 是异步任务，不是图像地址。状态 `/computation-api/process/{jobId}`；引擎结果 `/computation-api/process/result/{jobId}`；数值 TIFF `/computation-api/styles/cog/{jobId}`。
- 实测 GP 成功状态为 `resultStatus=1`、`resultFileStatus=1`、引擎 `status=success`；不套用旧文档的“2=成功”。结果中的 `processId=DAGJSON` 是过程类型，任务身份以 `jobId` 为准。

## 一次计算的内容

始终导出一个21波段 float32 GeoTIFF，包含原始数值和每个波段的 NoData。没有 `outputProduct` 或 RGB 产品切换参数。

| 分组 | 数值成果 | 后续用途 |
| --- | --- | --- |
| 变化 | 双期变化分类、两期水体、新增、持续、退水 | 主图、变化面积、卷帘核查 |
| 质量 | 两期观测质量、共同有效、可比较、指数分歧 | 区分不可判定与没有变化 |
| 指数 | 两期 NDWI/MNDWI 及各自差值 | 检查原值、解释分类依据 |
| 敏感性 | 九组阈值票数、九组一致范围、敏感性分类 | 比较基准结论对阈值的依赖 |
| 关注点 | 原始点位 ID、点位所在像元变化状态 | 与原矢量关联并核查局地状态 |

两指数分别取基准阈值及正负步长，组成九组独立组合。变化判定要求两期均有有效观测、每期两指数一致。指数分歧独立编码，不能强归为水体或非水体。票数是阈值敏感性，**不是概率或分类精度**。

源光学、SWIR、SCL和ID栅格必须已核实同原点、同范围；本服务固定 EPSG:32649、10米对齐网格。SWIR/SCL 的最近邻重采样不增加其原始空间细节。源反射率已处理偏移，只乘0.0001，不能再减0.1。源值非正、分母无效及不属于SCL 4/5/6的观测不纳入有效指数。

主分类：0稳定非水体、1持续水体、2新增水体、3退水、4指数分歧、5无共同有效观测。0在主地图中透明，但仍保留用于统计；5是有明确含义的分类值，不是栅格外部NoData。

## 平台与 Agent

`oge_get_service_definition` → `oge_execute_service` → 持久化任务 / `job_output` → 完整成果收集 → `map_present`。

执行前记录任务，编译或提交失败保存诊断；提交结果不明时不自动重试。重启只恢复状态查询与下载，不重复发起计算。代码执行与已发布GP服务使用各自明确的协议。

收集器核对全部波段名称和顺序，再无损拆成可独立渲染的单波段文件。原始完整 TIFF 保留供下载。21个产品在同一数据库事务发布，各自有output_id、路径、预览、图例、统计和共同来源；这不代表21次远端计算。成果卡按主题组织，工作区只展示一个完整成果入口。

点查直接点击地图；框选按下拖动松开即统计；多边形逐点绘制、双击完成；Esc退出并清除选区。图层栏决定查询对象，切换本组成果立即换图。选区随下一条消息传给Agent，用户不用重复传GeoJSON、填坐标或再点“应用”。统计结果在侧栏显示，不在绘制前打开弹窗。

全幅 summary 的面积为有效分类像元数乘投影网格像元面积，明确标注“网格面积”。`map_region_statistics` 使用选区内像元中心规则和 WGS84 椭球面积；两种口径不混用。分类编码的均值没有业务含义。

## 比赛案例演示

1. **总体判断**：“分析郁江这两期水体变化，并展示主要变化。” Agent读取服务契约、核实数据，调用一次，展示主图及分类面积。
2. **质量追问**：“为什么这块没有结论？” 直接点地图后提问。Agent读取该点及质量产品，区分无观测、指数分歧与稳定非水体。
3. **局地分析**：直接拖动圈出一段河岸，问“这片新增水体有多少？” Agent使用附带geometry和既有新增水体产品统计，不重新请求OGE。
4. **方法核查**：“这个结果对阈值敏感吗？” 切换敏感性分类与票数，解释基准与九组一致范围的区别。仍复用同一成果。
5. **时相对照**：展示灾前、灾后水体产品，点击卷帘即比较两幅可见图层；拖动分隔线核查局部变化。
6. **证据报告**：引用任务、参数、成果ID、选区、面积口径和局限。只有用户真正调整阈值或输入后才发起另一任务。

数值边界核验：对导出指数提升到float64后与Double阈值比较，可逐像元重建全部票数。直接用NumPy float32比较会在0.05附近出现少量舍入差异，不能据此修改远端判定或虚构精度。21个派生文件的数值掩膜及地图瓦片已实际读取验证。

关注点栅格实际包含13个ID，`poiMaxId=30`只是上限。两期观测为2026-06-22和2026-07-12，结果不代表洪峰最大淹没范围、淹没深度、受灾人口或实际损失。没有这些额外输入时，报告明确留下数据缺口。
