# OGE 洪涝遥感研判

## 确定范围与观测

从用户问题和附带的地图选区确定目标、研究范围及两期时间。用户给出时间段时，在各时间段内选景，并报告实际采集日期。对既有成果的解读、视图切换、点查和局部统计直接复用成果。

新分析先通过 `oge_get_service_definition` 查找能回答该问题的服务并读取其输入、参数和成果定义。服务要求账号内的上传栅格时，用 `oge_list_my_data` 读取栅格清单，根据资产名称、所属区域、采集日期和分辨率筛选，必要时继续翻页，并用 `oge_get_my_data_detail` 核对候选的范围和网格。名称关键词只匹配资产名，定位时同时使用所属区域和可核实的空间范围。检索公开影像时，用已经明确的地图范围，或用 `oge_find_regions` 解析行政区，再用 `oge_search_images` 查询两个时段。按覆盖、观测质量、采集时间和输入兼容性选择。

所选服务要求的输入必须齐备，且实际覆盖满足任务。缺少输入时说明缺哪一期、数据或范围；使用不同日期或更小覆盖时，在确认前说明变化。已登记的双期水体变化服务的输入准备和数值解读见[服务指南](references/service-guide.md)。

## 展示影像并等待确认

先发一条用户可见的消息，按前期、后期列出入选影像与实际日期，说明已核实的传感器、分辨率、覆盖范围及选择理由。单独标明辅助输入，并指出已知的观测缺口。以是否使用这些输入计算的问题收尾，在同一步调用 `oge_execute_service`，传入本次已核实的输入及参数，由该工具的审批卡等待一次确认。用户拒绝或取消时等待后续指示。

## 跟踪和上图

`oge_execute_service` 返回进行中的任务时，用 `job_output` 等待同一个 `job.id`。超时或提交状态不明时查询已有任务。执行失败时报告实际错误。

从实际成果选择能回答问题的主视图。使用 `map_present` 添加图层，传入 `analysis_output_id` 对应的 `output_id`、实际 `view_id` 及 `open_map: false, focus: false`。随后把返回的主图层 ID 交给 `map_focus`，打开地图并定位。需要看局部时，用已核实的范围定位。辅助视图按问题添加；用户要求目视对照时开启卷帘。需要核实渲染状态时用 `map_get_context` 传入 `include_screenshot: false`，以客户端反馈为准。

## 研判证据

根据成果元数据和统计解释持续水体、新增候选和退水，说明统计范围、面积口径、共同有效覆盖及观测缺口。两期各自的水体总量和同一可比范围内的增减分别报告。定位变化位置需有预览、点查或选区统计支撑。洪峰范围、水深、人口和损失需要独立资料。

局部追问使用消息附带的 `map_selection`，按图层匹配成果及视图，再用 `map_sample_raster` 点查或用 `map_region_statistics` 统计。阈值敏感性优先查阅已有成果；用户要求调整计算时，固定影像和统计范围，保留两次成果用于对比。

## 引导现场核查

主图上图后，用 `result_review_water_objects` 查询当前成果覆盖的公园和道路。根据实际返回的候选变化及九组阈值一致范围，指出一两个优先核查对象，提示用户从地图的「现场核查」列表点选定位。把无共同有效观测和指数分歧作为待补证据。用户说出对象名称时，带 `query` 查询已有成果，直接引用返回的统计和矢量来源；用户指定按圈选范围统计时，使用圈选几何。需要带用户看具名对象时，用返回的 `bounds` 调用 `map_focus`。

公园报告候选面积和统计覆盖，道路报告候选像元重合的中心线估计长度。说明矢量来源和影像时相。实际淹没、道路通行和设施损坏由现场核查确认。找不到对象时请用户在地图圈选或在坤舆工作区上传有名称和类型的 GeoJSON。
