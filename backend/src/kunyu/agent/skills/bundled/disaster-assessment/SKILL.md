# 灾害研判

1. 明确灾种、时间范围、分析区域和用户的决策问题。缺少关键条件时先说明缺口。
2. 使用 study_area_get 读取工作区保存的研究区。未设置时请用户绘制／导入，或在用户明确范围后使用 study_area_set 保存。地图视口不定义计算区域；研判开始时冻结研究区版本。
3. 将用户材料中的事实、可验证的推断和未知项分开。记录每条关键判断的材料来源与时间。没有实际获取数据时，不声称已读取遥感、气象、地形或监测资料。
4. 必要时通过 memory_read 读取本工作区已确认的偏好。不得将偏好当作灾害观测证据。
5. 使用 read 读取技能资源目录中的 references/brief-template.md，按其中结构生成研判。用户需要简短回答时合并栏目，但保留事实依据、不确定性和下一步行动。
6. 给出具体可执行的核查计划，列明所需数据和验证方法。没有执行能力时，把计算、空间叠加和脚本运行明确列为待执行工作。
7. 涉及人员安全时，避免用未经验证的结果指导撤离或通行；建议以属地应急部门的实时指令为准。

## 光学水体变化

先使用 read 读取 references/water-change.md。依次核实输入身份、日期、实际波段、辐射解释和共同有效观测。核心指数通过 oge_execute_code 在 OGE 计算；不要把本地验收结果描述为远端计算成果。

准备四个已保存、网格完全一致的单波段成果：前后期 MNDWI、前后期 SCL。使用 map_sample_raster 核查实际数值，使用 map_region_statistics 核对质量和分类面积。阈值必须说明依据；未经独立校准时 method_status 必须为 exploratory。

使用 assessment_create 生成固定格式成果包。它保存输入与研究区快照，基于两期共同有效观测做确定性变化分类、矢量化和面积统计，并生成 CSV、GeoJSON、Markdown/PDF。它不提交 OGE 计算，也不增加独立观测证据。完成后用 map_present 展示 output_id；报告和指标路径由工具实际返回。

每条关键结论区分观测、推断和未知项。两期持续水体不等同于永久水体；新增水体候选不等同于已核实洪涝；退水期影像不能代表洪峰最大范围。缺少耕地、道路、人口或现场资料时明确对应分析尚未完成。
