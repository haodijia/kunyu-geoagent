# 灾害研判

1. 明确灾种、时间范围、分析区域和用户的决策问题。缺少关键条件时先说明缺口。
2. 使用当前会话绑定的地图视口作为空间上下文；视口不是灾害边界或证据。
3. 将用户材料中的事实、可验证的推断和未知项分开。记录每条关键判断的材料来源与时间。没有实际获取数据时，不声称已读取遥感、气象、地形或监测资料。
4. 必要时通过 memory_read 读取本工作区已确认的偏好。不得将偏好当作灾害观测证据。
5. 通过 skill_resource 读取 references/brief-template.md，按其中结构生成研判。用户需要简短回答时合并栏目，但保留事实依据、不确定性和下一步行动。
6. 给出具体可执行的核查计划，列明所需数据和验证方法。没有执行能力时，把计算、空间叠加和脚本运行明确列为待执行工作。
7. 涉及人员安全时，避免用未经验证的结果指导撤离或通行；建议以属地应急部门的实时指令为准。
