# 提示词编辑入口

这里保存项目自己编写、发送给模型的提示词。正文由项目维护者编写；运行状态的默认说明也在本目录维护。Python 负责数据、参数约束和执行，不在组装时补写隐藏指导。

| 文件 | 修改内容 |
| --- | --- |
| `system.md` | 助手身份、业务定位、回答方式和行为边界 |
| `plan.md` | 计划模式指导，仅在计划模式启用时加入 System |
| `tool-guidance.yaml` | System 中的文件搜索、读取、写入操作指导；按插件是否启用贡献对应段 |
| `tools.yaml` | 24 个内置工具的模型可见说明，以及 `exit_plan_mode.plan` 参数说明 |
| `context.yaml` | 权限、审批、子 Agent 委派、时间、项目指令、Skill 目录和全文包装，以及计划／MCP／附件／压缩摘要包装 |
| `context-settings.yaml` | 可选时间和项目指令的开关、时区与刷新间隔；这里是运行配置，不是提示词正文 |
| `compaction.md` | `/compact` 和自动压缩使用的模型指令；至少保留一组不重复的 `## ` 标题，标题名称和数量可修改 |
| `tool-results.yaml` | 文件分段读取、搜索截断、图片缩放结果里的后续操作提醒 |
| `checks.yaml` | 设置页验证模型文本回答和工具调用能力的指令，不属于业务会话的 System |

Skill 本身的指令不放在这些包装文件中：

- 内置灾情研判：`../skills/bundled/disaster-assessment/SKILL.md`，配套文本在该 Skill 的 `references/`。
- 用户级 Skill：应用数据目录的 `skills/<名称>/SKILL.md`。
- 工作区级 Skill：应用数据目录的 `workspaces/<工作区 ID>/skills/<名称>/SKILL.md`。
- 桌面开发版应用数据目录为 `~/Library/Application Support/kunyu-electron/`。
- MCP 服务返回的工具说明和 instructions 来自该服务；本目录只编辑本项目的 MCP 包装文本。

## 修改与生效

直接编辑 Markdown 正文或 YAML 的文本值，保留 YAML 键名。`{{entries}}`、`{{instructions}}` 等占位符对应程序提供的数据，必须保留原变量集合；变量可重复使用和移动位置。变量缺失、未知变量、缺失文件和空文本都会明确报错，没有默认文案兜底。

修改后重启项目。System、工具说明和新注入的上下文使用新文本；Skill 目录指导有变化时会追加替换目录。旧请求快照和旧消息保留当时的原文，不回写。压缩请求会保存当次指令与摘要包装模板，后续改文案不会使历史回放依赖新文案。

工具的参数名称、JSON Schema 类型、约束和执行权限仍在 `agent/tools/` 中定义。这些是接口契约，不能通过修改说明文案改变执行行为。工具结果中的真实数据、状态码以及用户自己的输入也不属于提示词配置。

## 模型输入顺序

按 harness 的已提交消息历史与变化快照方式组装：

1. 组装有序 System 段：身份、计划策略、工具使用指导、MCP 服务指导。
2. 独立提供工具 schema，按工具名称排序。它是请求字段，不是一条消息。
3. 保留已有会话历史及其助手输出、工具调用和工具结果，追加本步骤接收的用户输入。
4. 需要时在新输入后追加项目指令快照、运行状态快照及可选时间信息；未变化且仍在可见历史中的状态不重复追加。
5. 首次发布或目录变化时追加 Skill 目录；用户明确调用的 Skill 全文随后追加。工具加载的 Skill 全文仍属于对应工具结果。

默认首次消息顺序为 `System → 用户问题 → 运行上下文 → Skill 目录`，工具定义是独立字段。第二轮保留这些消息和第一轮助手输出，追加新问题；状态或目录变化时才在新问题后追加更新。旧目录不会被移动到历史前面，也不会被最新目录覆盖。

压缩保留实际请求的 System 和工具定义，压缩选择的消息历史。已经压缩掉的运行状态、项目指令和 Skill 目录会在下一次模型步骤重新发布，避免只依赖摘要猜测当前状态。

不注入工作区、会话标识或地图快照，运行中引导消息也不附加地图信息。工具仍由服务端绑定工作区和会话权限，不需要模型提供这些标识。历史请求快照保留原文。

Chat、Messages、Responses 的 wire 字段由 SDK 编码；普通轮次保留已有消息前缀，供供应商利用前缀缓存。

## 运行上下文配置

默认提供本项目实际执行的文件工具权限、审批规则和只读子 Agent 约束。计划模式的有效文件权限也是只读。这里不声明未实现的操作系统沙箱、完全访问或可切换的审批预设。

`context-settings.yaml` 中默认关闭 `time_enabled` 和 `project_instructions_enabled`，不会主动读取项目文件或不断注入时间。修改开关后重启项目：

- 时间：`time_zone` 是 IANA 时区，默认 `Asia/Shanghai`。`time_refresh_seconds` 默认 300；设为 0 时每个模型步骤记录一次。刷新只在准备模型请求时发生，不创建后台定时任务。
- 项目指令：启用后读取托管文件区的 `/workspace/AGENTS.md`，以及已成功访问的文件所处目录及其祖先目录中的 `AGENTS.md`；根目录到子目录排序。原生路径位于应用数据目录的 `workspaces/<工作区 ID>/files/`。不读取开发仓库或其他主机目录，也不跟随符号链接。
- 项目指令删除或关闭后会追加清除说明；修改后追加新的完整快照。总正文上限 128 KiB，非法类型、读取失败或读取时变化会明确报错，不截断或静默跳过。

时间和项目指令是可选上下文能力；不需要时保持关闭即可。
