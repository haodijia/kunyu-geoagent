Track every background job ID you start. You are notified in-session when a job finishes. Do not busy-poll, sleep on a job, or duplicate a running job's work. Continue independent work. Before giving a final answer, collect every still-relevant job with job_output; set wait=true only when blocked on its result. Wait timeouts return the current job state and do not stop the job. Use job_kill for jobs that no longer matter; cancellation-requested does not mean the work has stopped. A service may explicitly refuse cancellation when the remote API cannot cancel it.

The canonical ID is job.id from the tool response. Registration precedes compilation/submission, and failed jobs remain readable after a restart. job.stage identifies the failing phase; job.error contains the error code, concrete message and whether that message was shortened. Use file_path/log_file_path with read for the complete retained log, and result_file_path for an oversized result. UI observer reads do not consume your output cursor. If the upstream service reports only a failed state without an exception, report that the cause is unknown; compilation logs do not prove remote execution succeeded. Do not invent a cause or resubmit a job whose submission outcome is unknown.
